# UI 디자인·상호작용 기준

급식 명단을 관리하는 실무자가 익숙한 조작으로 빠르게 작업할 수 있도록 하는 프로젝트 기준이다.
2026-09-29 사용자 피드백을 반영했다. 사용자의 최신 지시가 우선하며, 아래의 확인 절차는 별도 승인 절차를 뜻하지 않는다.

## 편집 조작의 일관성

- 명단 셀의 수정은 기존 열별 우클릭 메뉴를 진입점으로 사용한다. 새로운 열 하나에만 더블클릭 편집을 도입하지 않는다.
- 순서 셀은 **우클릭 → 순서 수정**으로 식종별 수정창을 연다. 인적사항 수정창으로 연결하지 않는다.
- 다른 열의 기존 우클릭 항목과 이력보기·민원 기능은 유지한다.
- 툴팁과 안내 문구는 실제 조작과 일치시킨다. 숨겨진 편집 제스처를 추가하지 않는다.
- 편집창은 현재 값을 채워 보여주고 저장·취소를 제공한다. 취소와 변경 없음은 DB 변경 기록을 만들지 않는다.
- 순서 수정은 변경한 식종의 순서만 저장하며 기사 배정은 유지한다. 날짜 제한 없이 적용된다는 점은 수정창에서 안내한다.

## 명단 표시

- 식종별 순서가 다르면 `/`로 이어 붙이지 않고 각 값을 별도 줄에 표시한다.
- 식종 이름과 값 사이에는 콜론과 공백을 쓴다. 현재 화면 식종 순서인 석식·조식·중식을 따른다.

```text
석식: 1
조식: 3
중식: 2
```

- 공통 순서 하나만 있으면 숫자나 기존 순서 문자열을 한 줄로 표시한다.
- `001` 같은 앞자리 0과 기존 순서 문자열을 임의로 숫자로 변환하지 않는다.
- 여러 줄 값이 잘리지 않도록 행 높이와 열 너비를 확인한다. 정렬·검색도 함께 확인한다.

## 기존 화면과 어울리는 디자인

- 색상과 글꼴은 `src/desktop_v2/theme.py`의 기존 규칙을 재사용한다.
- 기준 색은 짙은 남색 `#17313D`, 화면 배경 `#EDF3F5`, 경계선 `#CAD8DD`, 강조색 `#16788A`이다.
- 새 편집창의 저장 버튼에는 `primaryAction`, 취소 버튼에는 `quietAction` 등 기존 스타일을 적용한다.
- 기능을 추가할 때 상단에 기본 회색 버튼부터 붙이지 않는다. 조작 대상과 가까운 기존 위치에 배치한다.
- 여백·테두리·버튼 높이를 주변 요소와 맞춘다. 꾸미기 위한 색이나 영역을 추가하지 않는다.

## 접기·펼치기

- 좌우 패널은 각각 접고 펼칠 수 있게 한다. 상단의 글자 버튼 대신 얇은 경계와 중앙의 둥근 화살표 손잡이를 사용한다.
- 좌우 손잡이의 높이를 맞추고, 작은 시각 요소보다 넉넉한 클릭 영역을 제공한다.
- 접힌 상태에서도 손잡이와 화살표가 온전히 보여야 한다. 화살표 방향과 툴팁은 현재 가능한 동작을 나타낸다.
- 마우스 올림·누름·키보드 포커스를 구분한다. 전환은 약 150ms로 짧게 한다.
- 접으면 명단이 빈 공간을 채우고, 펼치면 상세 패널의 이전 너비를 복원한다.
- 날짜·식종·대상자 선택을 유지하며, 연속 클릭과 창 크기 변경에도 상태가 어긋나지 않게 한다.

## 완료 전 확인

- 합성 데이터로 펼침·접힘·수정창을 직접 캡처해서 확인한다. 실제 이용자 정보는 미리보기 자료로 사용하지 않는다.
- 기본 창과 최소 창 크기(현재 1080×680)에서 잘림, 겹침, 빈 공간, 손잡이 접근성을 확인한다.
- 새 수정 기능은 실제 진입 메뉴, 저장, 취소, 값 유지와 관련 회귀 테스트를 확인한다.
- 데이터 수정은 기존 revision·암호화 DB·자동 백업 흐름을 사용한다.

## 행 추가·삭제와 기사별 가구

- 명단에서 행을 추가하고 선택한 대상자를 삭제할 수 있는 조작을 제공한다. 빈 명단에서도 행 추가에 접근할 수 있어야 한다.
- 삭제는 대상자를 식별할 수 있는 확인창에서 `삭제`와 `취소` 버튼을 제공하고, `삭제`를 다시 눌렀을 때만 반영한다. 취소하면 데이터와 revision을 변경하지 않는다.
- 기사별 가구의 `식종별 분리` 버튼은 식종마다 해당 가구원·배송순서·연락처를 나누어 표시한다. `분리 해제`로 기존 가구별 표시로 돌아간다.
- 분리·해제는 조회 방식만 바꾸며 가구 구성이나 기사 배정을 저장·변경하지 않는다. 기사 선택과 검색·정렬을 유지하고 가구 수와 표시 행 수를 구분한다.
- 분리·해제 후 값 선택 필터에 더 이상 존재하지 않는 합친 값은 해제한다. 검색어와 유효한 값 선택, 명시적인 전체 선택 해제 상태는 유지한다.

## 배송 시작일과 비밀번호

- 행 추가 시 `배송 시작일`을 지정한다. 기본값은 명단에서 선택한 조회일이며, 선택한 식종은 지정한 날짜부터 가입·배송 대상으로 처리한다. 이전 날짜에는 배송 대상으로 표시하지 않는다.
- 배송 시작일 이후에는 식종별 기존 배송 일정과 상태 규칙을 적용한다. 추가 취소 시 데이터와 revision은 변경하지 않는다.
- 새 운영 파일은 비밀번호 하나로 생성·로그인·백업 복원을 진행한다. 별도 기관 복구 비밀번호를 요구하지 않고, 비밀번호 표시 기능으로 입력을 확인한다.
- 기존 두 비밀번호 방식의 파일과 백업도 일반 비밀번호로 계속 사용할 수 있게 한다. 기존 파일 여부와 관계없이 기관 복구 비밀번호 입력과 `비밀번호를 잊었어요` 기능은 제공하지 않는다.

## 전체 행 입력

- 행 추가창에서 성명·생년월일·취학유형·학교명·학년·반, 세대주 성명·아동과의 관계·관할동·제공기관, 주소·전화번호·핸드폰·비고와 DB에 정의된 사용자 항목을 입력할 수 있게 한다.
- 식종별 가입 여부·배송 담당·배송순서·초기 상태를 지정한다. 배송 시작일을 유지하고, 일시중지는 종료일도 입력한다. 선택하지 않은 식종의 배정·상태는 저장하지 않는다.
- 등록된 배송 기사는 이름이 같아도 구분해서 선택할 수 있게 하며, 기존 가구에 연결할 수 있는 선택 항목을 제공한다. 식별자나 변경번호 같은 내부 값은 자동으로 생성한다.
- 입력이 많아도 최소 창 크기에서 전체 항목에 접근할 수 있게 탭이나 스크롤을 사용하고, 추가·취소 버튼은 항상 보이게 한다.
- 새 사람·가구 연결·식종·배송 배정·초기 상태를 하나의 revision으로 저장한다. 잘못된 값이나 취소로 일부 항목만 저장되지 않게 한다.

## 방학 중식 명단 가져오기

- 기존 운영 명단이 있을 때 가져오기 목적에서 `방학 중식 명단 갱신`을 선택할 수 있다. 최초 DB 명단 가져오기와 구분한다.
- 지정한 적용일부터 중식 명단에 있는 사람은 배송, 기존 중식 배송 대상자 중 명단에 없는 사람은 미배송으로 자동 갱신한다. 이후 명단 갱신 때까지 적용한다.
- 누락 대상자를 일일이 확인하게 하지 않는다. 정확히 일치하는 사람은 자동 연결하고 새 사람은 자동 등록한다. 사람 연결이 모호하거나 원본의 필수 행에 오류·제외가 있으면 작업자가 먼저 해결한다.
- 모호한 사람 연결이 없으면 별도 최종 검토표를 띄우지 않는다. 최종 결과에는 기존 배송 유지·배송 재개·신규·미배송 전환 인원수를 보여준다. 조식·석식과 기존 인적사항·배송 배정은 유지한다.

## 헤더 필터와 조식 설정 정리

- 열별 검색은 엑셀 필터처럼 각 열 제목 옆 버튼으로 통합한다. 헤더 아래 상시 검색행은 표시하지 않는다. 명단 상단 전체 검색창은 별도로 제공하며, 전체 검색과 헤더 필터를 함께 적용한다.
- 헤더 버튼의 팝업에서 검색·값 선택·전체 선택·필터 해제를 제공한다. 적용해야 반영하고 취소하면 이전 조건을 유지한다. 전체 선택 해제는 0행으로 표시한다.
- 필터가 적용된 열은 버튼에서 구분한다. 열 제목 클릭 정렬과 필터 버튼 동작을 분리하며, 열 이동·크기 변경·가로 스크롤에도 버튼 위치를 유지한다.
- 별도 `조식 배송 규칙` 설정은 제공하지 않으며, 기존에 저장한 선택도 새 배송 리포트 계산에 적용하지 않는다. 기본 배송 일정과 날짜별 휴무·대체배송 설정을 사용한다. 과거 정책 이력은 삭제하지 않는다.

## 장기 미배송 보관함

- 대상자 테이블을 나누거나 행을 삭제하지 않고 일반 명단과 장기 미배송 보관함을 조회로 구분한다. 보관 여부는 배송·청구 계산이나 이력을 변경하지 않는다.
- 오늘을 기준으로 석식·조식·중식 모두 연속 미배송인 기간을 판단한다. 기준은 기본 365일이며 사용자가 변경할 수 있고 이 컴퓨터의 화면 설정으로 기억한다. 오늘을 포함한 최근 n일을 계산하며 개월 단위를 사용하지 않는다. 조회일을 과거로 바꿔도 보관 구분의 기준일은 오늘이다.
- 기간 안에 어느 가입 식종이든 배송 또는 일시중지 상태가 하루라도 있으면 보관 대상에서 제외한다. 미가입 식종은 배송 없음으로 보지만 신규·이력 부족 대상자를 임의로 장기 미배송으로 분류하지 않는다.
- 기본 화면은 보관 대상을 숨긴 일반 명단이다. 상단에 명단 종류·보관 기준·보관 인원을 상시 표시하지 않는다. `더보기 → 장기 미배송 보관함`에서 조회를 전환하고 `더보기 → 보관 기준 설정`에서 일수를 변경한다. 보관함에서도 전체 검색·헤더 필터와 이력보기를 사용할 수 있다. 배송 재개나 상태 수정 후 조건을 충족하지 않으면 일반 명단에 자동으로 다시 표시한다.

## 개인별 배송 설정과 가구 전체 적용

- 기본 식종은 석식·조식·중식 세 가지를 유지한다. 각 사람의 식종별 제공 요일·배송요일·형태를 각각 지정한다. 기본 적용 범위는 선택한 한 사람이며, `같은 가구 전체에 적용`을 선택한 경우에만 가구원에게 함께 반영한다. 별도 지정 체크 없이 값을 직접 수정하고 기본값과의 차이로 별도 설정을 자동 판정한다. 별도 배송 형태는 `도시락`, `식재료 박스`처럼 직접 입력한다. 형태가 달라도 같은 식종의 급식·청구 기준을 사용한다.
- 별도 요일은 해당 식종의 제공 요일이다. 예를 들어 석식을 월~금으로 지정하면 주말 석식은 제공하지 않고 금요일에 주말분을 묶어 제공하지 않는다. 휴일·대체배송 규칙은 기존 흐름을 따른다.
- 선택 정보의 `정보 수정` 옆 `배송 설정`에서 선택한 사람의 전용 창을 연다. 개인 적용과 가구 전체 적용의 이름·인원을 구분해서 표시한다. 가구에 연결되지 않은 사람도 개인 설정을 수정할 수 있다. 사람 정보 수정창의 배송 설정도 개인 적용이 기본이다.
- 제공 요일과 배송요일은 위아래로 맞춰 배치하고 배송 형태는 바로 입력한다. 식종별 `초기화`와 `전체 초기화`로 기본값을 복원한다. `기본값`·`별도 설정`과 아직 저장하지 않은 변경을 구분한다.
- 기본값과 같아진 항목은 기본값 상속으로 처리한다. 단, 기존 명시적 설정을 열기만 하거나 값을 원래대로 돌린 경우에는 revision을 만들지 않는다. 저장·취소는 기존 revision 및 백업 흐름을 따른다.
- 명단 필터에는 `별도 설정만` 체크 하나를 둔다. 선택하면 개인에게 실제 적용되는 별도 설정이 있는 대상자만 표시하고 배송 설정 상세 열을 보여준다. 해제하면 상세 열을 숨긴다. 같은 가구라도 개인 설정이 다르면 각각 구분한다.


## 선택 정보의 식종 이력과 배송요일

- 선택 정보의 식종 변경 이력은 식종과 변경 내용을 먼저 보여주고, 적용일·기간과 기록 시각을 별도 줄로 구분한다. 중요한 변경 내용을 한 줄 말줄임이나 툴팁에만 숨기지 않는다.
- 기간은 `2026-10-01 ~ 2026-10-05` 또는 `2026-10-01부터 · 종료일 미지정`처럼 표시한다. 시작일·종료일이 없으면 미지정임을 명시하며 `종료일=;` 같은 내부 키·구분자 표현을 노출하지 않는다. 원본 이력 값은 변경하지 않는다.
- 같은 가구 목록은 불필요하게 빈 공간을 차지하지 않도록 하고, 이력에는 여러 줄을 읽을 수 있는 공간과 스크롤을 제공한다. 제목 옆 `전체 보기`에서 기존 상세 이력 창으로 이동한다.
- 사람 정보 수정창의 식종별 요일 체크 바로 아래에 `배송요일` 줄을 둔다. 식사를 제공하는 요일과 실제 배송하는 요일을 구분하고, 여러 날짜의 식사가 한 배송에 묶이는 관계를 설명한다.
- 조식 기본 제공 요일은 금·토·일이며, 세 날짜의 식사를 금요일에 묶어 배송한다. 묶음배송해도 식수는 원래 제공일별로 계산한다.
- 배송요일 설정도 개인 적용을 기본으로 하는 저장·취소·기본값 복원 흐름을 따른다. 휴무·대체식의 명시적인 날짜별 지정은 유지한다.


## 앱 전체 긴 글 표시

- 앱 전체의 표·목록·트리·열 제목·선택 상자 등에서 긴 글을 `…` 또는 `...`로 바꾸지 않는다. 원문을 유지하고 공간이 부족하면 영역 경계에서 그대로 잘려 보이게 한다. 기존 줄바꿈·스크롤·전체 내용 툴팁은 유지할 수 있다.
- 메뉴와 안내 문구에도 불필요한 말줄임표를 붙이지 않는다. 표시 규칙 변경으로 저장 데이터나 복사할 원문을 바꾸지 않는다.


## 출력 템플릿 칼럼 연결

- 명단을 가져온 뒤에도 `설정 → 출력 칼럼 연결`에서 출력 연결을 수정할 수 있다. 원본 Excel을 다시 가져오게 하지 않는다.
- 양식(급식·행복도시락)과 문서(청구서·확인서)를 선택하고 `템플릿 칼럼`에 넣을 `명단 항목`을 지정한다. 지원하는 표준 항목·사용자 항목을 실제 이름으로 보여준다.
- 식수·청구금액·연번처럼 자동으로 생성하는 칼럼은 자동 계산임을 명시하고 임의의 명단 항목으로 바꾸지 못하게 한다. 확인서의 주소·관할동은 가구 묶음 기준으로 구분하여 수정 제한 이유를 표시한다.
- 별도 지정 체크 없이 기본 연결과의 차이를 판정한다. 현재 양식·문서의 초기화와 저장·취소를 제공하며, 양식 전환 때 저장하지 않은 변경을 조용히 버리지 않는다.
- 저장한 연결은 이후 새로 생성하는 문서에 적용한다. 기존 명단 값과 이미 만든 Excel은 변경하지 않는다. 연결 설정도 revision·자동 백업으로 보존하며 변경 없음과 취소는 기록을 만들지 않는다.
