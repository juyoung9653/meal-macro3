- `가구 묶기 기준`에서 별도 적용일 입력을 없애고 저장 즉시 반영한다. 과거 변경번호로 조회·출력할 때는 그 변경번호의 명단·기준·가구 연결을 사용한다. 가구 변경으로 개인별 식종·배송담당·배송 설정을 임의로 변경하지 않는다.
- 가구를 합치거나 나누면 영향을 받는 기사·식종별 배송 가구를 기존 순서대로 1부터 다시 매기고 명단 원본 배송순서에 함께 저장한다. 같은 가구·기사·식종의 배송 대상자는 같은 번호를 사용한다. 다른 기사 배정·식종 가입·중지 상태와 과거 변경번호는 보존한다. 이미 합쳐진 가구의 순서가 다르면 `가구 묶기 기준`을 다시 저장해 전체 순서를 정리할 수 있다.

- 문서 양식과 함께 운영 DB·변경 이력·백업에 저장하고 생성 기록에도 남긴다. 양식 전환 시 유지하며 취소·변경 없음은 저장하지 않는다.

## 핸드폰 자동 가구·동일인 연결·개인 예외 (2026-10-29)

- 명단 불러오기·직접 행 추가·번호 수정은 핸드폰으로 가구를 자동 연결한다. 이름·주소·세대주와 과거 저장 기준은 묶기 조건에 추가하지 않는다. 핸드폰 공용 예외도 가구 묶기에서 제외하지 않는다. 하이픈·공백은 무시하며 빈 번호는 서로 묶지 않는다.
- 같은 번호가 여러 기존 가구에 남아 있어도 가구 선택을 요구하지 않는다. 자동으로 합치고 나머지 공용 값이 다를 때만 값을 선택한다. 과거 소속·예약 소속은 변경 이력에 보존하며 현재 구성과 입력 변경은 한 번에 저장한다. 사람별 배송 동작은 유지한다.
- 일반·중식 명단 모두 이름＋핸드폰의 유일한 일치를 동일인 연결에 우선한다. 다른 동명이인 또는 생년월일 차이 때문에 이 연결을 다시 묻지 않는다. 이름＋번호가 같은 DB 기록이 여럿이거나 원본 중복 행이 충돌하면 확인을 받는다. 중식 연결 화면에는 번호 변경과 동명이인을 구별하는 설명을 표시한다.
- 값 충돌은 항목별로 일괄 방향을 먼저 고른다. `사람별 예외 보기`를 열면 해당 항목에서 값이 다른 사람을 모두 표시한다. 별도 사람 추가 단계 없이 직접 수정·기존 값·가져온 값 선택을 지원한다. `예외 해제`는 일괄 방향으로 복귀하고, 일괄 방향을 다시 바꾸면 해당 항목의 개인 예외도 초기화한다.
- 같은 학교의 약칭과 정식 명칭이 함께 있으면 정식 명칭을 자동으로 사용한다. `성남초/성남초등학교`, `성남중/성남중학교`, `성남고/성남고등학교`에 적용하며 높은 학년 선택과 별개로 처리한다. 학교 이름의 앞부분이 다르면 같은 학교로 취급하지 않는다.

## 중식 명단 가져올 행 조건 (2026-10-29)

- `명단 불러오기 → 방학 중식 대상자 갱신`의 열 연결 화면에 `전체 명단`·`선택한 칼럼에 값이 있는 행`·`선택한 칼럼이 특정 값인 행`을 제공한다. 조건 칼럼은 원본 Excel 열에서 선택하며 일반 열 연결·무시 여부와 별도로 사용한다. 처음 명단 불러오기는 전체 명단으로 처리하며 조건 UI를 표시하지 않는다.
- 값 있음은 공백만 있는 셀을 제외하고 숫자 0도 포함한다. 특정 값은 앞뒤 공백을 제외한 표시 문자열의 완전 일치로 비교하며 비교 값 입력은 필수다. 조건에 맞지 않는 행은 날짜·식종 등 상세 파싱 전에 제외하여 오류 행과 구분한다. 조건 칼럼의 수식 오류는 조용히 제외하지 않고 수정을 요구한다.
- 조건을 쓰면 저장 전에 선택된 명단과 조건 제외 건수를 미리보기에서 확인한다. 0명인 조건으로 저장할 수 없다. 기존 중식 갱신 규칙에 따라 조건에서 빠진 기존 중식 배송자는 중지됨을 조건 선택과 미리보기에서 안내한다.
- 선택 조건은 가져오기 프로필에 저장하여 같은 구조에서 다시 제안하고 일반 명단 불러오기로 전환하면 적용하지 않는다. 실제 제외된 원본 행 번호는 가져오기 이력에 보관하며 오류 때문에 제외된 행은 기존 검토 규칙을 유지한다.


## 확인서 1식 우선 배치 (2026-10-29)

## 핸드폰 기준 가구 자동 합치기 (2026-10-29)

- 기본 가구 기준은 핸드폰이다. 명단 셀·사람 정보에서 기준 칼럼을 수정하면 선택한 모든 값이 같으면 합치고 달라지면 별도 가구로 나누어 저장 즉시 적용한다. `가구 묶기 기준`에서 전화번호·주소·세대주·사용자 칼럼 등으로 기준을 바꿀 수 있다. 비고 등 칼럼을 가구 공용으로 켤 때도 저장된 기준이 같은 별도 가구를 다시 확인해 합친다. 합칠 공용 값이 다르면 확인 후 저장하며 취소하면 공용 설정과 합치기를 모두 저장하지 않는다. 기준값이 다르거나 비면 공용 설정만으로 합치지 않으며, 기준값을 바꾸지 않은 관계없는 기존 가구를 나누지 않는다. 핸드폰·전화번호의 하이픈·공백은 구분하지 않고 선택한 값에 빈칸이 있으면 묶지 않는다.
- 합칠 가구의 나머지 공용 칼럼 값이 다르면 기존 공용 값 확인창으로 칼럼별 값을 정한다. 현재 값 셀 선택·직접 입력·명시적인 비우기를 지원하고 공용 예외는 유지한다. 모든 검토 후 번호 수정·가구 소속·공용 값을 한 변경 이력과 자동 백업으로 저장한다. 검토 중 취소·실패하면 모두 저장하지 않는다.
- 이전 소속과 날짜는 변경 이력에 보존한다. 기준값이 달라지거나 비면 별도 가구로 나누고 공용 설정만 해제했을 때는 기준값을 유지한다. 이전 변경번호 복구는 원본 상태를 유지한다. 가구 소속이 바뀌면 명단·같은 가구·배송순서관리의 관련 표시를 함께 갱신한다.


## 확인서 플레이스홀더 연결·문서 원본 검색 (2026-10-28)

- 확인서 항목 설정은 연결된 양식의 확인서 시트에서 셀 전체가 `{key}` 형식인 플레이스홀더를 자동으로 찾아 실제 표기 그대로 나열한다. 1순위·2순위 명단 칼럼과 연결하고, 기존 제목·주차·식수 등은 자동 값을 기본으로 유지한다. 예전 항목명 기반 연결도 계속 읽는다.
- 일부 시트에만 있는 플레이스홀더도 편집·저장·출력할 수 있다. `전체 시트에 있지 않음 (있는 시트 수/전체 수)`과 없는 시트 목록을 표시하며, 출력은 해당 항목이 있는 시트에만 반영한다. 필수 항목 누락을 이유로 전체 확인서 생성을 막지 않는다. 연결하지 않은 새 항목은 빈칸으로 출력한다.
- `child1`·`phone2` 등 끝의 숫자는 가구원 순서이며 번호가 없는 명단 연결은 첫 가구원 기준이다. 주차별 식수는 사람·주차 번호를 구분한다. 주소·관할동 연결은 기존 DB 가구 묶음과 공통 출력값 검증을 유지한다.
- 문서 원본의 `이전 변경번호 선택`에서 검색창 하나로 변경번호·변경 내용의 이전/이후 값·사유·변경자를 검색한다. 검색어는 공백으로 나눈 단어를 모두 포함하는 기록을 찾고 검색 결과 없음·검색 지우기를 제공한다. 검색이 선택한 기록을 숨겨도 다른 변경번호를 자동 선택하지 않으며, 보이는 기록을 고르기 전에는 사용 버튼을 비활성화한다. 비밀번호 설정의 값은 내용 검색에서 제외한다.

## DB 조회·저장 성능 (2026-10-28)

- 한 세션에서 검증한 현재 명단과 변경 이력을 재사용한다. DB의 외부 변경·직접 SQL 변경·스키마 변경이 감지되면 재사용하지 않고 다시 검증한다. 처음 열기·명시적 무결성 검사·백업 복원에서는 전체 검증을 유지한다.
- 사람 정보만 수정한 경우 변경된 행을 검증하고, 변경되지 않은 식종 이력·일정·화면 설정 조회는 재사용한다. 식종 변경 취소·가구 변경·분기 전환 등 관련 상태가 바뀌는 작업은 필요한 전체 갱신을 수행한다. 검색·정렬·필터·선택은 유지한다.
- 자동 백업은 DB별로 별도 암호화 DB 하나(`.mealreplica`)와 비밀번호 정보 파일을 갱신한다. 처음에는 검증된 전체 사본을 만들고 이후에는 누락된 변경 기록·문서 생성 기록과 화면 설정을 반영한다. 저장마다 전체 파일 압축이나 SHA 계산을 하지 않으며 자동 압축 백업을 추가로 쌓지 않는다. 변경번호 목록은 검증된 정보를 재사용하고 저장 성공 시 새 기록만 반영한다. 저장 완료·백업 실패 구분과 대기 안내 기준은 유지한다.
- 새 별도 백업이 생성·검증된 뒤 같은 DB의 읽을 수 있는 기존 압축·증분 백업을 정리한다. 새 백업 실패 시 기존 파일을 유지하고, 다른 DB의 백업이나 식별할 수 없는 파일은 삭제하지 않는다. 복원 선택에서는 별도 DB 백업과 기존 압축 백업을 모두 지원한다. 별도 DB를 옮길 때는 함께 있는 비밀번호 정보 파일도 필요하다.

## 일반 명단 불러오기 불일치 검토·변경 기록 한국어 표시 (2026-10-28)

- 일반·중식 명단 모두 DB의 기존 값을 실제로 바꾸는 충돌만 확인한다. 동일 값·빈칸 유지·기존 빈칸에 새 값 채우기·학교 학년 자동 선택은 목록에서 제외한다. 나머지는 `주소 · 30명`처럼 항목별로 묶고 `가져온 값 사용 / 기존 값 유지`를 일괄 선택한다. 전체 항목에도 한 번에 같은 방향을 적용할 수 있다.

- 식종별 순서가 없으면 기존 기사 관리의 기본 순서를 따른다. 실제 순서를 변경한 식종만 운영 DB의 변경 이력·자동 백업에 저장한다. 재실행·다른 PC에서도 같은 운영 DB의 순서를 사용하며, 문서는 선택한 원본 변경번호의 순서를 적용한다. 새 기사는 별도 순서 뒤에 추가하며, 기존 이름 배정 등 등록 기사 이외의 출력 규칙은 유지한다.

- 배송대타의 `배송대타에 넣을 항목`은 칼럼 이름을 드래그하거나 위로·아래로 버튼으로 순서를 바꾼다. 목록은 평면으로 유지하고 드롭 위치를 표시한다. 체크 상태와 `값이 비어 있으면` 선택은 각 칼럼과 함께 이동한다. 숨긴 칼럼은 기존 자리를 유지하고 보이는 칼럼끼리 순서를 바꾼다. 기존 운영 파일별 순서 기억과 취소 동작을 유지한다.
- 위 기준은 아래 기존 일일식수 공통 기사 순서·배송대타 버튼 이동 기준보다 우선한다.
- HTML 설명서에 `7. 템플릿 변경`을 추가하고 시작 문서와 모든 장의 목차에서 연결한다. 양식 종류 선택, 일일식수·배송목록의 Excel 서식 수정·파일 연결·기본 양식 복원, 청구서·확인서의 항목 연결과 파일 교체 지원 범위를 실제 화면 기준으로 설명한다.

## 이력 일괄 취소·행 추가 접수 경로·상태 메뉴 (2026-10-26)

- 오른쪽 식종 이력과 개인 이력의 식종 변경 탭은 Ctrl·Shift 다중 선택을 지원한다. 선택한 항목을 우클릭하면 선택을 유지하고 `선택한 변경 N건 취소`를 제공한다. 선택 밖의 항목을 우클릭하면 그 항목만 대상으로 한다. 확인창에서 건수·대상·식종·기간·변경번호를 보여준다.
- 선택한 이력은 이후 기록부터 검사해 한 변경번호와 자동 백업으로 함께 취소한다. 함께 선택한 시작·후속 상태는 같이 되돌릴 수 있지만, 선택하지 않은 기록에 필요한 가입을 없애거나 다른 가구원의 기록을 자동 취소하지 않는다. 충돌·오래된 선택·저장 실패는 전체를 저장하지 않는다. 취소 후 명단·개인 이력을 갱신하며 원본 감사 기록은 유지한다. 이 다중 선택 기준은 아래 기존 한 건 취소 기준보다 우선한다.
- 행 추가의 가입·배송 영역에는 상태 변경창과 같은 `접수 경로` 선택을 둔다. 기본값은 미선택 `-`이며 선택지는 전화·메일·기타다. 선택한 가입 식종에 공통 적용해 변경 이력과 함께 저장하고 개인·선택 정보·월별 식종 이력에도 표시한다. 취소는 저장하지 않는다.
- 식종 셀 우클릭의 상태 메뉴는 명단 조회일의 현재 상태에 맞춘다. 배송이면 일시중지·중지, 중지이면 배송, 일시중지이면 배송·일시중지·중지를 표시한다. 여러 셀은 모든 선택 셀에서 가능한 동작만 표시한다. 미가입 등 상태가 없는 셀의 기존 메뉴와 배송담당·이력보기·민원은 유지한다.

## 다른 사용자 화면 설정 가져오기 (2026-10-26)

- `설정 → 다른 사용자 화면 설정 가져오기`에서 같은 운영 DB에 저장된 다른 Windows 사용자를 선택하고 시트 목록·숨김 칼럼 수를 확인한 뒤 가져온다. 이름이 같아도 사용자 식별자로 구분하고 PC 이름·저장 시각을 함께 표시한다.
- 가져오기는 이 PC의 해당 DB에 대한 시트 이름·순서·선택된 시트와 칼럼 순서·너비·숨김·표시 이름을 교체한다. 즉시 적용하고 재실행 후에도 유지한다. 검색·필터·조회 날짜·명단 데이터·다른 사용자의 원본 설정은 유지하며, 취소·잘못된 설정은 적용하지 않는다. 현재 명단에 없는 칼럼은 표시하지 않는다.
- 사용자별 화면 설정 사본은 같은 암호화 DB에 명단 변경 이력과 별도로 저장한다. 앱에서 DB를 열고 종료할 때, 가져오기 완료 때 현재 사용자의 사본을 갱신한다. 처음에는 해당 버전으로 DB를 연 사용자의 설정만 제공하며, 가져올 사용자가 없으면 이 조건을 안내한다. 기존 로컬 설정은 보존하며 가져오기로 명단 변경번호를 만들지 않는다.

## 월별 식종 변경 정렬·조회창 복귀 (2026-10-26)

- 월별 식종 변경은 기본으로 최신 변경번호가 위, 이전 변경번호가 아래에 오도록 표시한다. 같은 날짜의 변경번호 순번도 숫자로 비교한다.
- 열 제목 클릭은 메인 명단처럼 오름차순·내림차순·해제 순서이며 먼저 선택한 열부터 다중 정렬한다. 헤더에 방향·우선순위를 표시하고 필터 버튼과 분리한다. 모든 정렬을 해제하면 최신 변경번호 순서로 돌아간다. 월 변경·새로고침에도 열린 창의 정렬·필터를 유지한다.
- 월별 조회에서 지연 로딩 안내가 닫히면 월별 조회창을 다시 앞으로 활성화한다. 식종 변경의 단독 창도 같은 동작을 적용하며, 조회 실패 안내도 해당 창에서 바로 확인할 수 있게 한다.
- 공통 지연 진행창을 사용하는 조회·저장·문서 생성·내보내기도 진행창이 닫히면 작업 전 활성 창과 입력 위치로 돌아온다. 작업 전 창을 찾을 수 없으면 보이는 부모 창을 사용하며, 이미 닫힌 창을 다시 열지 않는다. 작업 도중 다른 창으로 이동했거나 이후 새 확인·완료창이 열린 경우 그 창의 포커스를 빼앗지 않는다. 진행창이 뜨지 않은 빠른 작업은 활성 창을 강제로 바꾸지 않는다.

## 식종 변경 접수 경로·비고 (2026-10-26)

- 식종 변경창에서 접수 경로는 선택 사항이며 미선택은 `-`로 표시한다. 기간 아래에 여러 줄 비고 입력칸을 제공하고, 선택한 대상·식종에 동일한 비고를 변경 이력과 함께 저장한다. 비고는 명단의 개인 비고와 별개이며 취소하면 저장하지 않는다.
- 개인 식종 변경 이력은 `식종 / 구분 / 접수 경로 / 기간 / 비고 / 변경자 / 변경번호` 순서로 표시한다. 선택 정보의 식종 이력도 접수 경로를 기간 앞에, 비고를 기간 뒤에 표시한다. 과거 기록에 접수 경로가 없으면 `-`, 비고가 없으면 빈칸으로 표시하며 자동 생성 사유를 비고로 대신 사용하지 않는다.
- 월별 조회의 식종 변경 이력은 `성명 / 식종 / 구분 / 접수 경로 / 적용 기간 / 비고 / 변경자 / 변경번호` 순서로 표시하고 접수 경로·비고에도 열 필터를 제공한다. 종료일 없는 기간은 `yyyy-mm-dd ~ `처럼 끝 날짜를 비워 표시한다. 위 기준은 아래 기존 이력 열 구성보다 우선한다.
- 선택한 식종별 시작일에 이미 배송 상태이면 배송, 이미 중지 상태이면 중지를 다시 저장하지 못한다. 미가입 식종의 신규 배송 시작은 허용한다. 개별·일괄·같은 가구 적용에 같은 검사를 하며, 중복 대상이 있으면 대상자·식종·날짜를 안내하고 전체 변경을 저장하지 않는다.
- 청구서의 식종 이력 문구에서 연속된 일시중지는 하나의 기간으로 합치고, 일시중지에 이어 중지가 적용되면 일시중지 시작일부터 하나의 중지로 표시한다. 배송 기간이나 공백을 사이에 둔 기록은 합치지 않는다. 원본 상태 사건과 개인·선택 정보·월별 변경 이력은 개별 기록을 그대로 유지하며, 취소된 기록은 출력에서도 제외한다.

## 일시중지 자동변환 (2026-10-26)

- `설정 → 일시중지 자동변환`에서 `같은 달 안에서 자동변환`·`자동변환 안 함` 두 가지만 선택한다. 기본값은 같은 달 안에서 자동변환이다.
- 종료일 없는 중지 이후 종료일 없는 배송으로 재개할 때, 중지 시작일과 배송 재개일의 연도·월이 같으면 중지일부터 재개 전날까지 일시중지로 해석한다. 월말 중지 후 다음 달 1일에 재개하는 경우도 중지를 유지한다. 자동변환을 끄면 같은 달이어도 중지를 유지한다. 직접 입력한 일시중지는 변경하지 않는다.
- 설정은 운영 DB의 변경 이력·자동 백업으로 저장하며 같은 DB를 쓰는 사용자에게 공통 적용한다. 저장 후 명단과 이력을 갱신하고 조회일·검색·필터·선택을 유지한다. 취소·변경 없음은 기록을 만들지 않는다.
- 기존 원본 중지·배송 기록과 원본을 보여주는 개인·월별 변경 이력은 유지한다. 명단과 문서 계산의 유효 상태는 선택한 원본 변경번호의 설정으로 해석하며, 설정이 없던 변경번호도 같은 달 기본값을 사용한다. 기존 기록 조회에도 적용된다는 점을 설정창에 안내한다.

## 배송대타 칼럼 선택 (2026-10-26)

- 배송대타의 `배송대타에 넣을 항목` 목록에는 실제 명단 칼럼을 표시한다. 칼럼 이름을 그대로 출력 제목으로 사용하고, 체크로 출력 여부를 정하며 위로·아래로 버튼으로 순서를 바꾼다. 출력 제목을 별도로 고르거나 첫 번째 값을 선택하는 드롭다운은 제공하지 않는다.
- 각 칼럼 옆에 `값이 비어 있으면` 선택칸 하나를 둔다. 자기 칼럼의 값이 없거나 공백일 때만 지정한 대체 칼럼의 원래 값을 사용하며, 둘 다 비면 비운다. 숫자 0은 유지한다. 대체값을 사용해도 제목은 원래 칼럼 이름을 유지하고 다른 대체 연결을 연쇄 적용하지 않는다.
- `설정 → 배송대타 칼럼 표시`의 `모든 시트에서 숨긴 칼럼 제외`는 기본 선택이다. 현재 시트에 숨겨져 있어도 다른 시트 하나에서 보이면 목록에 포함한다. 제외한 칼럼은 출력하지 않고 새 대체값 선택 목록에도 넣지 않는다. 이미 지정한 대체값이 숨겨졌다면 `저장된 대체 칼럼 (현재 목록에 없음)`으로 보존하고 원본에 없으면 출력 전에 안내한다.
- 숨김 제외를 해제하면 전체 칼럼을 선택할 수 있다. 숨김 제외 여부·출력 체크·순서·용지 설정은 이 PC의 운영 파일별로, 대체 칼럼은 추가로 식종별로 기억한다. 취소는 선택값을 저장하지 않는다. 숨김으로 제외한 항목의 기존 체크·대체 선택은 지우지 않아 다시 표시할 때 복원한다.
- 배송대타는 별도의 출력 칼럼 연결 화면을 제공하지 않는다. 설정 메뉴는 `청구서·확인서 항목 설정`으로 표시하고 두 문서만 다룬다. 새 배송대타 선택 흐름은 이전의 첫 번째 값 연결을 사용하지 않으며, 과거 설정 기록과 기존 문서는 보존한다.
- 배송담당·실제 정렬·원래 연락처 기준 가구 묶음·관할동별 페이지·식수·BOX 집계는 칼럼 선택과 대체값에 영향을 받지 않는다. 문서 생성 이력에는 실제 칼럼 이름·선택·대체값을 기록한다.

## 더보기 메뉴 정리 (2026-10-22)

- 더보기는 `명단·파일`, `기사·배송`, `조회·기록`, `운영·설정` 네 분류와 12개 진입 항목으로 구성한다. 아래 기준은 기존 문서에 남아 있는 이전 메뉴 경로보다 우선한다.
- `명단·파일`에는 Excel 명단 불러오기, Excel 내보내기, 장기 미배송 보관함을 둔다. Excel 내보내기는 현재 시트와 전체 데이터를 고른 뒤 기존 내보내기 작업을 실행한다.
- `기사·배송`에는 기사 관리와 배송순서관리를 둔다. 배정 일괄 교체는 기사 관리 안에서 열고 선택한 기사와 명단 조회일을 초기값으로 전달한다. 저장하지 않은 기사 순서가 있으면 먼저 저장하도록 안내한다.
- `조회·기록`에는 월별 조회, 전체 변경 이력, 전체 민원을 둔다. 월별 조회는 공통 연월 선택과 식수·식종 변경 탭을 사용한다. 탭을 바꾸거나 새로고침하면 최신 자료를 읽고 식종 변경 탭의 열 필터는 유지한다.
- `운영·설정`에는 운영 일정, 단가 관리, 칼럼 관리, 설정을 둔다. 운영 일정의 학교 일정·휴무·공휴일 탭에서 해당 관리 화면을 연다. 각 화면의 기존 저장·취소·가져오기 흐름은 유지한다.
- 칼럼 관리는 독립 창으로 제공한다. 표시·숨김 체크는 현재 시트에 바로 적용하며 기본 배치 복원, 사용자 항목 추가·삭제, `칼럼 가구 공용 설정`을 제공한다. 가구 공용 설정 버튼을 누른 뒤 펼쳐지는 목록에서 칼럼을 선택하며, 현재 공용인 칼럼은 체크로 표시한다. 칼럼을 미리 선택할 필요가 없고 목록을 닫기만 하면 변경하지 않는다. 열 제목 우클릭에 전체 관리 항목을 추가하지 않는다.
- `별도 설정만`은 더보기에서 제거하고 메인 검색 영역의 필터 체크박스로 둔다.

## 구주소 수동 업데이트

- 변환 중에는 전체 명단의 처리 인원·전체 인원과 백분율을 표시한다. 건너뜀·동일·조회 실패도 처리가 끝난 인원에 포함하며, 중복 주소의 조회 재사용과 관계없이 사람 단위로 센다. 기존 1초 지연 표시와 진행 중 닫기 제한을 유지한다. 조회 처리 100%는 저장 완료를 뜻하지 않으며 이후 저장·백업은 별도 진행 안내와 최종 결과로 확인한다.

- 구주소 업데이트 실행 시 API 키가 없으면 경고 메시지 창에 `API키 입력`·`확인` 두 버튼을 표시한다. `API키 입력`은 주소 API 키 설정창을 바로 열고, `확인`·Esc는 경고만 닫는다. 키 설정창을 닫으면 기존 칼럼·업데이트 조건을 유지한 업데이트 창으로 돌아오며, 키 저장만으로 자동 실행하지 않는다.
- `설정 → 주소 API 키`에서 도로명주소 검색 API 승인키를 입력·확인·삭제한다. 키는 Windows 자격 증명 관리자에 PC·사용자별로 저장하며 운영 DB·백업·공통 설정 파일에는 저장하지 않는다. 입력값은 기본으로 가리고 표시 선택을 제공한다.
- `설정 → 구주소 업데이트`에서 신주소를 읽을 칼럼 하나와 구주소를 저장할 문자형 사용자 칼럼을 선택한다. 입력 기본값은 `도로명주소`이며 관할동은 자동으로 붙이지 않는다. 검색어 앞에 `경기도 성남시`를 붙인다. 이미 `경기도 성남시`로 시작하면 중복하지 않고 `성남시`로 시작하면 `경기도`만 보완한다. 입력 주소가 비면 지역명만으로 조회하지 않고 건너뛴다. 입력·출력은 같은 칼럼을 선택할 수 없다. 구주소 칼럼이 없으면 새 칼럼 생성도 선택할 수 있다.
- `구주소가 비어 있는 건만 업데이트`를 기본으로 하고 `전체 업데이트`는 기존 값도 갱신한다. 화면의 검색·필터·숨김과 관계없이 전체 명단을 대상으로 하며 창을 연 조회일 기준 주소를 사용한다고 안내한다. 자동 조회하지 않고 `업데이트 실행`을 눌러야 조회한다.
- 신주소 없음·조회 실패·모호한 결과·입력 제한 위반은 기존 값을 유지한다. 성공한 변경만 하나의 변경번호와 자동 백업으로 저장한다. 서비스 전체 오류·저장 충돌은 일부 결과를 저장하지 않는다. 변경 없음·취소는 새 칼럼과 변경번호를 만들지 않는다.
- 결과에서 변경·동일·건너뜀·실패 인원과 실패 대상을 표시한다. 저장 직후 메인 명단을 갱신하고 기존 조회일·검색·필터·선택을 유지한다.

급식 명단을 관리하는 실무자가 익숙한 조작으로 빠르게 작업할 수 있도록 하는 프로젝트 기준이다.

## 문서 원본 변경번호

- 문서 만들기는 작업을 시작할 때 변경 이력의 순서가 가장 높은 변경번호를 원본으로 선택하고 바로 기간 화면을 연다. 원본 확인만을 위한 별도 단계는 두지 않는다. 기간 화면에는 선택된 변경번호를 간단히 표시하고, `이전 변경번호 선택` 버튼을 누르면 변경번호 목록을 바로 연다. 과거 변경번호를 선택하거나 최신으로 돌아올 수 있다. 목록을 취소하면 기간과 원본 선택을 유지하고, 기간 화면을 취소하면 문서를 만들지 않는다.

## 일일식수 배송 형태 선택

- 일일식수 문서의 식종 선택 화면에는 선택한 원본 변경번호의 배송 설정에 저장된 형태를 표시한다. 처음에는 모든 식종과 `기본`·각 별도 형태를 선택한다. `선택한 식종 사용`으로 확정한 식종과 제외한 배송 형태는 운영 DB의 변경 이력과 함께 저장하며 다른 PC에서도 같은 DB를 열면 복원한다. 뒤로·취소는 저장된 선택을 바꾸지 않는다. 새로 추가된 형태는 포함하고, 과거 원본에 잠시 없는 형태의 제외 설정은 유지한다. 식종이나 배송 형태를 하나도 선택하지 않으면 진행할 수 없다.
- 선택하지 않은 형태의 배송 대상은 가구 수와 식수, 이전 배송일 비교에서 모두 제외한다. 같은 가구에 여러 형태가 있으면 선택한 형태의 구성원만 계산한다. 저장 위치 확인 화면에는 선택한 형태를 다시 표시한다.
- 배송담당은 각 실제 배송일에 저장된 배정 기록으로 판단한다. 선택 기간 밖의 이전 배송일에만 배송담당이 빠졌다면 현재 문서 생성은 진행하고 해당 이전 배송일 비교의 증감 표시는 생략한다. 선택 기간 안의 배송담당 누락은 오류로 안내한다.


## 문서 생성 오류의 대상자·위치 안내

- 가구 소속 기록의 누락·시작일·종료일은 문서 생성 오류로 처리하지 않는다. 선택한 원본 변경번호의 현재 가구를 사용하고 소속이 없으면 안정적인 1인 가구로 처리한다.
- 그 밖의 문서 오류는 원본 변경번호·기간과 현재 화면의 검색·필터·정렬을 반영한 명단 행 번호를 구분해서 표시한다. 저장되지 않은 원본 Excel 행·열 번호를 추정하지 않는다.

## 식종 이력 등록 취소

- 명단 오른쪽 식종 변경 이력 또는 개인 이력의 식종 변경 탭에서 한 건을 선택해 등록을 취소할 수 있다. `중지`·`일시중지`는 선택한 상태 기록만 취소하고 남아 있는 이력에 따른 이전 상태로 돌아간다. 신규 가입을 만든 `시작`은 해당 가입만 취소하며, 기존 가입의 배송 재개 기록은 그 상태 기록만 취소한다.
- 취소한 항목은 개인·식종 이력에서 사라지고 별도 `취소` 행을 표시하지 않는다. 원래 감사 기록은 보존하고 취소 내용은 새 변경번호의 전체 변경 이력에만 남긴다. 저장 후 명단·열린 개인 이력은 즉시 갱신되며 다시 열어도 같은 결과를 표시한다.
- 가구 공용 식종 상태가 설정되어 있으면 한 건 취소로 예외가 아닌 구성원끼리 상태가 달라지지 않도록 검사한다. 충돌하면 공용 설정·예외를 확인하도록 안내하고 저장하지 않는다.
- 이후 변경에 필요한 가입을 없애거나 다른 이력을 함께 취소하지 않는다. 다른 기록 때문에 한 건만 취소할 수 없으면 이유를 안내하고 저장하지 않는다. 선택 뒤 새 변경이 저장되면 최신 이력을 다시 읽도록 안내한다.

## 편집 조작의 일관성

- 명단의 성명·생년월일·학교·학년·전화번호·핸드폰·도로명주소·상세주소·관할동·비고·사용자 항목은 셀을 더블클릭해 현재 표시값을 직접 수정한다. Enter와 다른 곳으로의 정상적인 포커스 이동은 저장하고 Esc는 취소한다. 변경 없음·잘못된 값·저장 실패는 revision과 화면 값을 바꾸지 않는다.
- 식종 셀은 더블클릭으로 수정하지 않는다. 주소·관할동의 `이사 등록`은 해당 셀의 우클릭 메뉴에서만 열고, 배송 설정은 기존 배송 설정 수정 흐름을 연다.
- 메인 명단의 순서 셀은 읽기 전용이다. 더블클릭·키보드로 편집창을 열지 않고 우클릭 메뉴에도 `순서 수정`을 제공하지 않는다. 인적사항 수정창으로 연결하지 않는다. 순서 표시는 유지하고 툴팁에서 배송순서관리를 안내한다. 배송순서관리 화면의 순서 편집·저장은 유지한다.
- 다른 열의 기존 우클릭 항목과 이력보기·민원 기능은 유지한다.
- 툴팁과 안내 문구는 실제 조작과 일치시킨다. 숨겨진 편집 제스처를 추가하지 않는다.
- 편집창과 셀 편집기는 현재 값을 채워 보여준다. 취소와 변경 없음은 DB 변경 기록을 만들지 않는다.
- 인적사항·명단 셀 수정이 저장되면 명단과 오른쪽 같은 가구 정보를 즉시 갱신하고 조회일·검색·필터·정렬 및 화면에 남은 대상자와 칼럼 선택을 유지한다. 수정한 대상자가 필터에서 사라지면 다른 행을 임의로 선택하지 않는다.
- 순서 수정은 변경한 식종의 순서만 저장하며 기사 배정은 유지한다. 입력칸을 비워 저장하면 해당 식종의 순서를 지우고, 기존 공통 배정의 순서가 다시 나타나지 않게 한다. 날짜 제한 없이 적용된다는 점은 수정창에서 안내한다.

## 이사 시 관할동 변경

- `정보 수정` 또는 명단 셀에서 주소·관할동을 직접 바꾸면 변경한 항목만 과거와 현재 조회에 즉시 반영한다. 미래 날짜의 이사 예약은 해당 날짜부터 그대로 적용한다. 가구 공용 항목은 수정일의 같은 가구 중 해당 항목의 예외가 아닌 구성원에게 함께 정정하며, 예외인 사람이 수정하면 다른 구성원에게 전파하지 않는다.
- `이사 등록`에서 주소와 함께 관할동을 직접 입력한다. 선택 목록으로 제한하지 않는다.
- 관할동은 명단의 현재 조회일 기준 값을 채워 보여주고, 주소와 같은 적용일부터 변경한다. 빈칸으로 저장하면 해당 날짜부터 관할동을 지운다.
- `같은 가구 구성원도 함께 이사`를 선택하면 주소와 관할동을 하나의 revision으로 같이 적용한다. 취소하거나 변경한 내용이 없으면 revision을 만들지 않는다.

## 명단 표시

- 식종 칼럼의 `중지`는 실제 중지 적용 기간의 시작일을 기준으로 설정한 기간 동안 빨간색으로, 그 뒤에는 미가입과 같은 회색 `#82949A`로 표시한다. 기본값은 시작일이 속한 당월이다. `설정 → 중지 표시 기간`에서 당월·당일·N일(시작일 포함, 기본 30일)을 이 PC의 운영 파일별로 기억한다. 기간 판정에는 컴퓨터 오늘 날짜가 아닌 명단 조회일을 사용한다. 적용 시작일을 알 수 없는 중지는 회색으로 표시하며 색상 설정은 상태·집계·청구를 변경하지 않는다.

- 명단은 도로명주소와 상세주소를 서로 붙이지 않고 나란한 별도 열로 표시한다. 각 열의 검색·필터·이름·숨김과 현재 시트 Excel 내보내기도 구분한다. 두 주소 열은 더블클릭해 직접 수정하고 `이사 등록`은 우클릭 메뉴에서 열며, 행 추가에서도 각각 입력한다.
- 기존 주소 열의 내부 키·사용자 이름·너비·순서를 유지하고 새 상세주소 열은 바로 다음에 배치한다. 이전 주소 열이 숨겨져 있으면 새 상세주소 열도 처음에는 숨긴다. 이전 합친 주소에 적용된 저장 검색·값 선택 필터는 최초 복원 시 해제하며 다른 열의 필터는 유지한다.
- 도로명주소·상세주소의 가구 공용 여부와 예외는 각각 독립적으로 설정한다. 선택한 칼럼만 검토·저장·전파하고, 다른 주소 칼럼은 각 사람의 적용일 기준 값을 유지한다. 기존에 주소 묶음으로 저장한 공용·예외 설정은 두 칼럼 모두에 적용된 것으로 읽으며 이후 각각 변경할 수 있다.
- 출력 칼럼 연결에서는 실제 명단에 등록된 칼럼만 선택할 수 있다. 도로명주소와 상세주소는 각각 선택하며, 합성 항목인 `전체 주소 (도로명주소 + 상세주소)`는 1순위·2순위 모두 제공하지 않는다. 실제 사용자 칼럼의 이름이 `전체주소`인 경우에는 별도 항목 ID로 구분하여 선택할 수 있다. 기존 합성 주소 연결은 편집창에서 `비움`으로 표시하고 저장 시 빈 연결로 반영하며, 열기·취소만으로 저장된 연결이나 기존 문서를 변경하지 않는다.

- 왼쪽의 현재 조회 인원은 `조회 명단`으로 표시한다. 메인 검색 영역에는 `전체 기사` 선택 상자를 두지 않으며, 기사 조건은 열 제목 필터로 선택한다. 배송순서관리는 더보기의 기사 관리에서 열며 한 기사만 선택한다.
- 왼쪽 식종별 현황은 조회일이 운영 파일의 식종별 기본 배송요일이고, 조회 결과에 배송 또는 일시중지가 한 명 이상인 식종만 표시한다. 기본 제공요일에 연결된 실제 배송요일로 판단하므로 금·토·일 조식을 금요일에 묶어 배송하면 조식 현황은 금요일에만 표시한다. 저장된 `휴무·공휴일` 일정에서 조회일의 해당 식종이 `미제공`이면 현황을 숨긴다. `정상 운영`으로 변경하면 기존 배송요일·인원 조건에 따라 다시 표시하며, `대체식 제공`을 미제공으로 처리하지 않는다. 필터·조회 날짜·명단·배송 기본값·휴무 일정이 바뀌면 바로 다시 표시하거나 숨긴다. 명단 칼럼과 오른쪽 같은 가구 목록의 현재 상태 표시는 이 현황 표시 조건과 분리한다.
- 표준 `비고`는 명단 열과 전체 검색에 포함한다. 사용자가 만든 `비고2` 같은 추가 항목은 별도 열과 값으로 그대로 유지하며 표준 `비고`와 합치거나 덮어쓰지 않는다.
- 배송 상태를 선택하거나 이력으로 표시할 때는 `배송`·`일시중지`·`중지`를 사용한다. 명단 식종 칼럼의 현재 상태는 조회일의 가입 기간과 상태 이력으로 판단하며, 반복 제공 요일과 실제 배송요일은 적용하지 않는다. 중식은 추가로 조회일이 검토된 학교 일정 기간 안의 업체 제공 대상일 때만 상태를 표시한다. 학교 일정이 없거나 기간 밖인 날·학교 급식일·주말은 `-`로 표시하되, 학교 급식일에 학교 미급식 학년으로 지정된 대상은 업체 제공 대상으로 본다. 배송 중이면 `배송`, 일시중지면 `일시중지`를 표시하며 중지되었거나 미가입인 식종의 상태 줄은 `-`로 표시하고 배송 담당 줄은 유지한다.
- 오른쪽 선택 정보의 제목은 `같은 가구`로 표시한다. 가구원별 식종은 선택일에 명단 식종 칼럼의 현재 상태가 `배송`인 식종만 표시한다. 배송일이 아니어도 포함하며, 일시중지·중지·미가입 식종은 제외한다. 가구 목록 높이는 현재 글꼴의 행 높이에 맞춰 최대 5명까지 온전히 표시하고, 더 많은 가구원은 목록 안에서 스크롤해 확인한다. 대상자를 바꾸면 목록 맨 위부터 표시하며 식종 변경 이력 공간은 유지한다.
- `같은 가구`는 조회일과 가구 연결 기간에 관계없이 현재 가구의 구성원을 표시한다. 소속 기록이 없으면 본인을 1인 가구로 표시한다. 식종 표시는 실제 조회일의 가입·상태를 따른다.
- `중지`를 새로 선택하면 종료일 없음이 기본이다. 일시중지에서 전환할 때도 같으며, 사용자가 종료일을 다시 지정하면 입력한 날짜는 유지한다.
- 배송 상태 변경창의 식종 카드는 체크박스뿐 아니라 현재 상태 문구와 빈 공간을 눌러도 선택을 전환한다. 체크박스의 키보드 조작은 유지하고, 일괄 변경 대상이 아닌 비활성 식종 카드는 어느 영역을 눌러도 선택하지 않는다.
- 배송 상태 변경창은 식종별로 시작일·종료일을 따로 입력한다. 여러 식종을 한 번에 선택해도 각 식종의 기간을 하나의 revision으로 저장하며, 선택을 해제했다가 다시 선택해도 입력한 기간을 유지한다.
- 상태 변경의 시작일과 유한한 종료일은 운영 파일의 `식종별 배송 기본값`에서 제공 요일이 연결된 실제 배송 요일로만 입력한다. 허용 요일을 식종별 기간 입력 옆에 표시하고, 달력에서 허용하지 않는 날짜는 흐리게 표시하며 선택할 수 없게 한다. 마우스·키보드·날짜 증감·직접 입력 모두 허용하지 않는 날짜를 확정하지 않으며, 유효한 날짜 직접 입력과 월·연도 이동은 유지한다. 종료일 없음으로 설정한 배송·중지는 종료일을 검사하지 않는다.

- 식종별 순서가 다르면 `/`로 이어 붙이지 않고 각 값을 별도 줄에 표시한다.
- 식종 이름과 값 사이에는 콜론과 공백을 쓴다. 현재 화면 식종 순서인 석식·조식·중식을 따른다.

```text
석식: 1
조식: 3
중식: 2
```

- 순서가 하나이거나 여러 식종의 순서가 같아도 `석식: 1`처럼 식종을 표시한다. 조회일의 가입 식종과 명시적으로 보존된 식종별 배정만 표시하며, 미가입 상태에서 공통 배정만 남은 값은 `공통/식종 미지정: 1`로 구분한다.
- `001` 같은 앞자리 0과 기존 순서 문자열을 임의로 숫자로 변환하지 않는다.
- 여러 줄 값이 잘리지 않도록 행 높이와 열 너비를 확인한다. 정렬·검색도 함께 확인한다.

## 기존 화면과 어울리는 디자인

- 색상과 글꼴은 `src/desktop_v2/theme.py`의 기존 규칙을 재사용한다.
- 기준 색은 짙은 남색 `#17313D`, 화면 배경 `#EDF3F5`, 경계선 `#CAD8DD`, 강조색 `#16788A`이다.
- 새 편집창의 저장 버튼에는 `primaryAction`, 취소 버튼에는 `quietAction` 등 기존 스타일을 적용한다.
- 기능을 추가할 때 상단에 기본 회색 버튼부터 붙이지 않는다. 조작 대상과 가까운 기존 위치에 배치한다.
- 여백·테두리·버튼 높이를 주변 요소와 맞춘다. 꾸미기 위한 색이나 영역을 추가하지 않는다.

## 여러 창을 함께 사용하기

- 일반 조회·설정·편집·문서 준비 창을 열어 둔 상태에서도 메인 명단을 검색하고 수정할 수 있다. 열린 편집창의 대상자와 기준 날짜는 메인 선택을 바꿔도 유지한다.
- 일반 작업창은 Windows 작업 표시줄의 창 목록과 Alt+Tab에서 각각 선택할 수 있어야 한다. 작업 표시줄의 아이콘 묶음 여부는 Windows 설정을 따른다. 창 크기·최대화 복원과 재표시 후에도 유지한다. 작업 창을 열어 둔 상태에서 메인 창이나 다른 작업 창을 클릭하거나 Alt+Tab으로 선택하면 선택한 창이 앞에 표시되어야 한다. 작업 창을 메인 창에 종속된 항상-위 창으로 고정하지 않는다. 확인 메시지·파일 선택·로그인·진행 안내는 별도 작업창으로 등록하지 않는다.
- 편집창을 연 뒤 다른 창에서 운영 데이터가 저장되면 이전 내용을 덮어쓰지 않는다. 저장 충돌을 알리고 입력 내용을 남겨 복사할 수 있게 하며, 취소하고 다시 열어 최신 내용으로 수정하도록 안내한다.
- 메인 창을 닫으면 열린 작업 창도 정리하며 닫힌 운영 파일에 저장을 이어가지 않는다. 로그인·작업 진행·삭제와 복구 확인·파일 선택은 해당 작업에 필요한 기존 확인과 대기 방식을 유지한다.

## 기다림 안내 창

- 새로고침·저장·문서 만들기·Excel 내보내기 등 작업이 시작된 뒤 1초가 지나도 끝나지 않았을 때만 안내 창을 표시한다. 1초 안에 끝난 작업은 안내 창을 띄우지 않으며, 완료 뒤 늦게 나타나지 않도록 한다.
- 안내 창이 나타나기 전에도 같은 작업을 중복 실행하지 않도록 하고, 성공·실패 후에는 화면 조작을 다시 활성화한다.

## 시작 시 운영 데이터 불러오기

- 비밀번호 확인 뒤 운영 파일을 열고 명단·변경 이력을 준비하는 동안 진행 중 창을 표시한다. 진행률을 계산할 수 없는 작업이므로 움직이는 막대와 현재 작업 안내를 사용한다.
- 데이터 읽기는 화면 응답을 막지 않게 처리한다. 진행 중에는 Esc와 닫기 조작으로 창을 없앨 수 없으며, 작업이 성공하거나 실패하면 진행 중 창을 먼저 닫은 뒤 운영 화면 또는 오류·가져오기 안내를 표시한다.
- 진행 중 창은 기존 시작 화면의 글꼴·남색·청록색과 카드 여백을 재사용하며 실제 이용자 정보를 표시하지 않는다.

## 접기·펼치기

- 좌우 패널은 각각 접고 펼칠 수 있게 한다. 상단의 글자 버튼 대신 얇은 경계와 중앙의 둥근 화살표 손잡이를 사용한다.
- 좌우 손잡이의 높이를 맞추고, 작은 시각 요소보다 넉넉한 클릭 영역을 제공한다.
- 접힌 상태에서도 손잡이와 화살표가 온전히 보여야 한다. 화살표 방향과 툴팁은 현재 가능한 동작을 나타낸다.
- 마우스 올림·누름·키보드 포커스를 구분한다. 전환은 약 150ms로 짧게 한다.
- 접으면 명단이 빈 공간을 채우고, 펼치면 상세 패널의 이전 너비를 복원한다.
- 날짜·식종·대상자 선택을 유지하며, 연속 클릭과 창 크기 변경에도 상태가 어긋나지 않게 한다.

## 완료 전 확인

- 합성 데이터로 펼침·접힘·수정창을 직접 캡처해서 확인한다. 실제 이용자 정보는 미리보기 자료로 사용하지 않는다.
- 기본 창과 최소 창 크기(현재 1080×680)에서 잘림, 겹침, 빈 공간, 손잡이 접근성을 확인한다.
- 새 수정 기능은 실제 진입 메뉴, 저장, 취소, 값 유지와 관련 회귀 테스트를 확인한다.
- 데이터 수정은 기존 revision·암호화 DB·자동 백업 흐름을 사용한다.

## 운영 데이터 위치 변경

- 기존 운영 파일의 저장 위치는 `설정 → 운영 데이터 위치`에서 변경한다. 새 파일 위치와 현재 비밀번호를 입력하고 완료하면 운영 창을 종료하며, 다음 실행부터 새 위치를 사용한다.
- 열린 DB의 백업과 검증된 복원으로 최신 내용 및 비밀번호 정보를 함께 옮긴다. 기존 파일과 설정은 취소·실패 시 유지하고 대상 파일은 덮어쓰지 않는다.

## 자동 백업 폴더 변경

- `설정 → 자동 백업 폴더`에서 현재 폴더를 확인하고 새 폴더를 지정한다. 저장하면 실행 중인 세션과 다음 실행에 바로 적용하며 운영 창을 닫지 않는다.
- 새 폴더에 검증된 백업을 만든 뒤 설정을 저장한다. 취소·변경 없음·실패는 기존 백업 위치를 유지한다. 운영 데이터 파일의 위치는 바꾸지 않는다.
- 기존 백업은 원래 폴더에 보관한다. 폴더를 변경할 때 기존 백업을 옮기거나 삭제하지 않는다.

## 운영 파일 비밀번호 변경

- `설정 → 운영 파일 비밀번호 변경`에서 현재 비밀번호와 새 비밀번호·확인을 입력한다. 입력 값은 기본으로 가리고 표시 기능을 제공한다.
- 현재 비밀번호 오류·확인 불일치·취소·변경 없음은 자격 정보와 revision, 자동 백업을 바꾸지 않는다. 변경 성공 후에도 운영 창을 유지하고 결과를 안내한다.
- 설정된 자동 백업 폴더의 현재 별도 백업 DB는 비밀번호 정보 파일을 원자적으로 교체해 새 비밀번호로 갱신한다. 폴더 밖의 복사본과 갱신 실패 백업은 변경 전 상태로 보존하며, 마지막으로 해당 백업을 열던 비밀번호는 파일마다 다를 수 있다. 손상·확인 불가 백업은 유지하고 사용자에게 알린다. 비밀번호 변경 후 백업 갱신에 실패해도 운영 파일의 변경 완료와 일부 실패를 분명히 안내한다.

## 행 추가·삭제와 배송순서관리

- 명단에서 행을 추가하고 선택한 대상자를 삭제할 수 있는 조작을 제공한다. 빈 명단에서도 행 추가에 접근할 수 있어야 한다.
- 삭제는 대상자를 식별할 수 있는 확인창에서 `삭제`와 `취소` 버튼을 제공하고, `삭제`를 다시 눌렀을 때만 반영한다. 취소하면 데이터와 revision을 변경하지 않는다.
- 배송순서관리의 `식종별 분리` 버튼은 식종마다 해당 가구원·식종·연락처를 나누어 표시한다. `분리 해제`로 기존 가구별 표시로 돌아간다.
- 분리·해제는 조회 방식만 바꾸며 가구 구성이나 기사 배정을 저장·변경하지 않는다. 기사 선택과 검색·정렬을 유지하고 가구 수와 표시 행 수를 구분한다.
- 분리·해제 후 값 선택 필터에 더 이상 존재하지 않는 합친 값은 해제한다. 검색어와 유효한 값 선택, 명시적인 전체 선택 해제 상태는 유지한다.
- 배송순서관리의 열별 검색어·값 선택은 현재 운영 파일별 PC 화면 설정으로 기억한다. 명시적으로 값을 하나도 선택하지 않은 상태와 현재 표시 데이터에 없는 저장 값도 복원한다. `숨긴 명단 포함`은 다시 열 때 기본 해제 상태로 시작한다.
- `전체 필터 해제`는 배송순서관리의 모든 열 검색과 값 선택 조건을 한 번에 지우고 저장한다. 식종별 분리·숨긴 명단 포함·선택한 기사는 유지한다. 행은 저장된 배송순서로 표시하며 헤더 클릭 정렬은 제공하지 않는다.

## 배송 시작일과 비밀번호

- 배송담당 변경창은 식종별 체크와 기사 선택만 제공한다. 별도의 공통 기사 선택 상자와 `선택 식종에 같은 기사 지정` 버튼은 제공하지 않는다.
- 행 추가 시 식종별 `배송 시작일`을 지정한다. 식종별 기본값은 명단에서 선택한 조회일 이후 첫 실제 배송일이며, 선택한 식종은 각자 지정한 날짜부터 가입·배송 대상으로 처리한다. 이전 날짜에는 해당 식종의 배송 대상으로 표시하지 않는다.
- 행 추가의 배송 시작일은 `식종별 배송 기본값`의 제공 요일과 요일별 실제 배송일을 함께 적용한다. 조식을 금·토·일 제공하고 금요일에 묶어 배송하면 조식 시작일은 금요일만 허용한다. 허용 요일을 각 입력 옆에 표시하고, 허용되지 않은 날짜는 안내 후 저장하지 않는다.
- `행 추가`로 새로 등록하는 사람의 최초 가구 소속은 시작일 제한 없이 저장한다. 추가일·배송 시작일 이전 조회에도 본인 또는 연결된 가구가 표시되며, 식종 가입·상태·배송 담당의 시작일과 배송·청구 기준은 유지한다. 이미 저장된 소속 기간은 자동 변경하지 않는다.
- 배송 시작일 이후에는 식종별 기존 배송 일정과 상태 규칙을 적용한다. 추가 취소 시 데이터와 revision은 변경하지 않는다.
- 새 운영 파일은 비밀번호 하나로 생성·로그인·백업 복원을 진행한다. 별도 기관 복구 비밀번호를 요구하지 않고, 비밀번호 표시 기능으로 입력을 확인한다.
- 기존 두 비밀번호 방식의 파일과 백업도 일반 비밀번호로 계속 사용할 수 있게 한다. 기존 파일 여부와 관계없이 기관 복구 비밀번호 입력과 `비밀번호를 잊었어요` 기능은 제공하지 않는다.

## 행 추가 입력

- 기존 가구와 연결할 때 공용값이 다르면 다른 항목만 확인창에 표시한다. 새 대상자의 값을 맞게 수정하거나 항목별로 새 대상자 예외를 지정해 행과 예외를 하나의 변경으로 등록한다. 기존 가구원은 변경하지 않는다. 입력 화면으로 돌아가거나 저장에 실패해도 입력값을 유지한다.
- 행 추가창은 명단에 등록된 칼럼 중 직접 입력하는 인적사항·사용자 항목만 제공하고, 현재 표시 이름을 사용한다. 명단에 없는 취학유형·세대주 성명·아동과의 관계 등의 내부 입력칸을 따로 만들지 않는다. 도로명주소와 상세주소는 명단과 같이 별도 칸에 입력한다. 화면에서 잠시 숨긴 등록 칼럼은 입력할 수 있다.
- 가입 식종과 식종별 배송 시작일, 식종별 배송 담당을 지정한다. 배송 담당은 등록 기사 또는 미지정을 선택하며 가입하지 않은 식종에는 배정하지 않는다. 담당 배정은 각 식종의 배송 시작일부터 적용하고, 시작일이 같은 식종은 하나의 배정 기록으로 묶어 새 사람·가입·가구 연결과 하나의 revision으로 저장한다. 배송순서·초기 상태는 추가 후 기존 수정 기능을 사용한다.
- 기존 가구를 직접 고르는 항목은 제공하지 않는다. 저장된 가구 묶기 기준을 사용하고, 기준이 없으면 핸드폰을 기준으로 삼아 현재 구성원과 자동 연결한다. 빈 값이나 일치하지 않는 값은 연결하지 않는다. 여러 가구가 일치하면 함께 합치며, 공용값이 다르면 확인 후 하나의 변경으로 저장한다.
- 입력이 많아도 최소 창 크기에서 전체 항목에 접근할 수 있게 탭이나 스크롤을 사용하고, 추가·취소 버튼은 항상 보이게 한다.
- 새 사람·자동 가구 연결·식종 가입을 하나의 revision으로 저장한다. 잘못된 값이나 취소로 일부 항목만 저장되지 않게 한다.
- 배송 시작일 입력은 마우스 휠로 값이 바뀌지 않게 하며, 키보드 입력과 달력 선택은 유지한다.

## Excel 명단 불러오기

- 열 연결 전용 창은 `문서에 사용하는 칼럼` → `식종` → `나머지 칼럼`의 세 구역으로 나눈다. 문서 사용은 현재 청구서·확인서 항목 연결을 기준으로 하며, 엑셀 타일이 연결되었는지와 구분한다. 각 구역에 제목·설명·칼럼 개수를 표시하고 기존 청록색·남색·밝은 회색 제목 배경과 여백으로 구분한다. 구역 안은 기존 타일 줄바꿈·드래그·클릭 연결을 유지하고 빈 구역도 칼럼 없음으로 안내한다. 식종 연결은 별도 식종 구역에 모은다.
- `원본 연번`은 원본 파일과 대조하기 위한 번호를 불러오기 이력에 보관하는 선택 항목이다. 명단 칼럼이나 배송순서가 아니라는 설명을 연결 자리의 툴팁에 표시한다.
- 명단 불러오기에서는 도로명주소 열을 하나만 연결한다. `도로명주소 · 빈칸 대체` 타일·주소 2순위 선택·기존주소 자동 대체 연결은 제공하지 않는다. 이전 가져오기 설정의 주소 대체 연결도 새 가져오기에는 적용하지 않으며 대체 열은 대기 영역으로 돌아간다. 과거 가져오기 기록과 문서 출력의 빈칸 대체 설정은 유지한다.
- 오류 정정표의 모든 행 높이는 글꼴·스타일이 적용된 값 입력칸의 실제 최소 높이 이상으로 통일한다. 텍스트 입력·드롭다운, 오류 한 행·여러 행 모두 같은 칸 높이를 사용하고 입력칸이 아래 행을 가리거나 겹치지 않게 한다.

- 가져오기 화면에는 열 연결 개수·가져오지 않는 개수·다시 연결할 개수와 `열 연결 확인하기` 버튼을 강조해 표시한다. 열 연결은 필수 단계이며 전용 창의 `연결 확인 완료`를 누르기 전에는 가져오기를 진행하지 않는다. 확인 전 하단 진행 버튼도 `열 연결 확인`으로 표시하여 전용 창을 열도록 한다. 원본 파일·표·가져오기 방식이나 실제 열 연결이 달라지면 다시 확인한다. 버튼을 누르면 타일 매핑만 담은 별도 창을 최대화해서 열며, 그 안에서 모든 DB 칼럼을 바둑판으로 표시한다. 창 크기를 바꿔도 타일 줄바꿈·문서 사용 칼럼 우선·드래그 자동 스크롤을 유지한다.
- 매핑 전용 창은 기존 연결 상태를 직접 편집한다. `연결 확인 완료`는 현재 연결을 확인한 것으로 처리하고 가져오기 화면으로 돌아간다. 닫기·Esc는 편집한 연결을 유지하지만 미확인 연결을 확인 완료로 처리하지 않는다. 닫기 자체로 DB를 저장하지 않으며 실제 저장은 기존 `가져오기` 흐름을 따른다. 중복 창이나 중첩 이벤트 루프를 만들지 않고, 가져오기 종료·단계 이동·자료 검사 시 매핑 창도 닫는다.
- `설정 이름` 입력란은 제공하지 않는다. 새 열 연결 프로필의 이름은 원본 파일명(확장자 제외)으로 자동 기록하고, 저장된 연결을 다시 사용할 때는 기존 이름을 유지한다. 이력에 필요한 프로필 이름·ID·버전은 계속 보관하며 사용자가 이름을 정할 필요는 없다.

- 학교 유형·세대주 성명·아동과의 관계를 표준 항목으로 연결하면 명단에도 해당 칼럼을 표시한다. 저장된 가져오기 설정으로 빈 칼럼도 유지하며, 예전에 저장한 값이 있으면 재가져오기 없이 표시한다. 가져온 적도 값도 없는 항목은 추가하지 않는다. 이 칼럼도 검색·셀 수정·행 추가·출력 칼럼 연결에서 같은 저장값을 사용한다.
- 열 연결은 DB 칼럼 제목과 원본 타일 자리를 한 묶음으로 각 구역의 바둑판에 제공한다. 전용 창 안에서는 모든 DB 칼럼을 표시하고 화면 너비에 맞춰 아래 줄로 내린다. 칼럼별 접기나 검색은 추가하지 않는다. 현재 청구서·확인서 양식에서 사용하는 기본 연결·저장된 연결·빈칸 대체 칼럼을 첫 구역에 두고 `문서 사용`을 표시한다. 이름이 아닌 원래 항목 키·사용자 칼럼 ID로 사용 여부를 판정하며 전체 주소는 도로명주소·상세주소를 포함한다. 문서 양식이 설정되지 않으면 사용 칼럼을 임의로 정하지 않는다. 양식을 읽지 못하면 저장된 연결로만 우선 표시하고 안내하며 명단 불러오기는 계속할 수 있다.
- 자동 연결·저장된 연결의 원본 타일은 처음부터 해당 DB 칼럼 안에 놓는다. 타일에는 원본 열 문자·이름과 값 예시를 표시하고 툴팁으로 전체 내용을 확인한다. 아래에는 `아직 연결하지 않은 엑셀 칼럼 · 가져오지 않음` 영역과 `새 DB 칼럼 추가 (문자)` 영역을 둔다. 타일을 끌어 놓거나 타일 선택 후 목적지를 클릭해 연결한다. 이미 타일이 있는 DB 칼럼에 놓으면 기존 타일은 대기 영역으로 돌아온다. 대기 영역에 놓으면 가져오지 않음으로 바꾸고 새 칼럼 영역에는 여러 원본 타일을 각각 추가할 수 있다.
- 타일을 작게 줄여 한 화면에 넣지 않는다. DB 칼럼은 세로 스크롤로 아래쪽 자리를 확인하고, 전체 설정도 아래로 이어질 수 있다. 드래그 중 DB 칼럼 영역이나 전체 설정 영역의 위·아래 가장자리에 머무르면 해당 영역을 자동 스크롤한다. 드래그를 마치거나 취소하면 자동 스크롤도 멈춘다. 마우스 휠·스크롤바와 키보드로 타일·목적지를 선택하는 동작을 함께 지원한다.
- 현재 DB의 기본 칼럼 표시 이름과 사용자 칼럼 이름·자료형을 유지하며, 연결은 표시 이름이 아닌 칼럼 ID로 저장해 이름을 바꿔도 유지한다. 삭제된 대상은 다시 선택하도록 안내하며 같은 대상에 두 원본 열을 연결하지 않는다. 화면 배치·우선순위는 실제 저장할 값이나 기존 가져오기 프로필 형식을 바꾸지 않는다.

- `원본 종류`는 사용자가 선택하지 않는다. 기존 가져오기 설정의 출처 정보는 유지하고 새 파일은 자동으로 기록한다.

- 연결하지 않은 열은 기본으로 `가져오지 않음`이다. `새 칼럼 추가 (문자)`를 선택하면 원래 열 이름으로 만들고, 같은 이름이나 빈 머리글은 원본 열 문자로 구분한다. 기존 사용자 칼럼은 숫자·날짜·선택형을 유지하며 맞지 않는 값은 원본 셀별로 수정한다. 문자형의 여러 행 값은 기존처럼 보존한다. 저장한 가져오기 설정에는 기존 칼럼 연결·새 칼럼·제외 선택을 함께 기억한다. 이름만으로 대상이 둘 이상이면 자동 연결하지 않는다.
- 방학 중식 방식에서는 일반 식종 형태 안내와 `열 연결 바꾸기` 버튼을 숨기고 별도 식종 열 연결을 비활성화한다. 상단 `가져올 중식 명단`의 전체·값 있음·특정 값 조건으로 대상을 정하며, 선택된 명단 포함 여부로 중식 배송을 갱신한다. 일반 방식으로 돌아가면 기존 식종 연결과 안내를 복원한다.
- 파일 안의 모든 Excel 표를 목록으로 보여주고 가져올 표를 선택한다. 이름이 `명단`인 표를 기본 선택하고, 없으면 목록의 첫 표를 선택한다. 선택 목록에는 표 이름만 표시한다.
- 선택한 Excel 표의 머리글과 데이터 범위를 자동으로 사용한다. Excel 표에서는 시트·헤더 행·데이터 시작 행을 별도로 지정하지 않으며 합계 행과 표 밖의 셀은 가져오지 않는다.
- Excel 표가 없는 두 줄 병합 머리글은 일반 시트 그대로 가져올 수 있다. 위쪽 병합 제목 아래에 둘 이상의 개별 제목이 있으면 자동으로 두 줄 모드를 제안한다. 자동 인식이 맞지 않거나 다른 시트를 읽으려면 `헤더 읽기 → 2줄 헤더`에서 시트와 `헤더 시작 행`을 지정한다. 데이터 시작은 두 번째 머리글 다음 행이다. 일반 한 줄 범위는 기존처럼 Excel 표로 만들도록 안내한다.
- 두 줄 머리글은 물리적인 열마다 연결한다. 가로 병합 폭이 작은 개별 제목을 우선하고 폭이 같으면 아래쪽 제목을 사용한다. 아래쪽 제목이 없으면 위쪽 제목을 사용하며 세로 병합은 해당 열의 제목으로 유지한다. 중복 제목도 열 문자로 구분한다. 머리글 병합이 데이터 행까지 이어지면 가져오기를 막고 시작 행을 확인하도록 안내한다.
- 자동 연결과 저장된 연결은 모두 수정할 수 있다. 머리글 시작 행·행 수·열별 연결·추가 항목 선택을 확정 가져오기의 DB 이력에 함께 저장한다. 같은 머리글 구조가 하나만 일치하면 저장 설정을 다시 제안하고, 수정한 연결은 새 버전으로 저장한다. 원본 파일은 수정하지 않는다.
- 선택 항목은 `가져오기 방식`으로 표시하고 `일반 명단 반영`·`방학 중식 대상자 갱신`을 제공한다. 최초 가져오기처럼 방식이 하나뿐이면 해당 항목을 표시하지 않는다. 표시 이름 변경으로 기존 처리 규칙은 바꾸지 않는다.
- 가져오기 방식 선택칸 바로 아래에 현재 선택의 설명만 작은 회색 글씨로 표시한다. 일반 명단은 `학교·학년은 높은 쪽을 유지하고, 빈칸은 기존 값을 유지하고 충돌하는 값만 항목별로 선택합니다.`, 방학 중식은 `파일에 있는 대상자는 중식 배송, 빠진 기존 중식 배송자는 중지로 반영합니다.`로 안내하며 `빠진 기존 중식 배송자는 중지`만 굵게 표시한다. 별도 상자·버튼은 두지 않으며 최초 가져오기에서는 방식 선택과 함께 숨긴다.
- 적용일은 열 연결 단계에서 선택한다. `가져오기`를 누르면 오류·불일치·모호한 연결만 검토한 뒤 저장한다. 명단 전체 미리보기나 별도의 마지막 확인은 띄우지 않는다.
- 새 운영 파일의 최초 명단은 적용일 기본값으로 이번 달 1일을 제안한다. DB를 만든 날짜와 명단의 실제 적용일을 구분하며, 사용자가 날짜를 바꾸면 그 날짜로 저장한다. 기존 명단 갱신·방학 중식 갱신의 기본값과 실제 신규 대상자의 배송 시작일은 유지한다.
- 가져오기 검사에서 오류나 성명 누락 등 제외 행을 발견하면 오류 정정 창을 자동으로 먼저 연다. 사용자는 값을 고치거나 `행 제외` 체크로 원본 행 전체를 가져오지 않을 수 있다. 한 원본 행에 여러 오류가 있으면 체크를 함께 동기화하고 해당 행의 값 편집을 비활성화한다. `수정·제외 적용 후 가져오기`로 나머지 행을 다시 검사하며 남은 오류가 있거나 가져올 사람이 0명이면 저장하지 않는다. 일반 선택 항목의 빈칸은 계속 허용한다.
- 명시적으로 제외한 원본 행 번호는 가져오기 이력에 저장하며 원본 Excel은 변경하지 않는다. 이번 파일·표에만 적용하고 새 원본·표·연결 변경 시 초기화하며 저장된 열 연결 프로필에는 넣지 않는다. `수정·제외 모두 취소`로 원본 기준 재검사를 할 수 있다. 중식도 명시적 행 제외를 허용하되 제외된 기존 중식 배송자가 중지될 수 있음을 정정 창에서 안내한다. 아직 수정하거나 명시적으로 제외하지 않은 중식 오류·누락 행은 저장을 막는다.
- 가져오기 가구 묶기는 `설정 → 데이터 관리 → 가구 묶기 기준`에서 선택한 칼럼을 사용한다. 설정이 없으면 핸드폰을 기본으로 하며, 예전 가져오기 전용 기준은 현재 기준으로 사용하지 않는다. 선택한 모든 값이 같고 비어 있지 않을 때만 묶는다.
- 값 정리 선택 UI는 제공하지 않는다. 생년월일은 자동 인식, 전화번호는 한국 전화번호 형식 자동 정리를 적용한다. 과거 수동 정리 설정을 재사용해도 새 가져오기는 자동 방식으로 기록하며, 자동 정리가 불가능한 값은 오류 정정·행 제외 대상으로 처리한다.
- 연결 검토 창은 `명단 반영 방법을 선택해주세요`로 안내하고 표는 `번호 / 성명 / 생년월일(중식은 핸드폰) / 행 반영 방법`을 기본 표시한다. 번호는 현재 검토 목록에서 1부터 매기는 표시용 순번이며 원본 연번·엑셀 행 번호와 구분한다. 중복되는 `분류`, `원본 위치`, `인적사항 변경`, `식종 변경`, `같은 사람 후보`, `기존 가구 후보` 열은 표시하지 않는다. `반영 방법 선택`에서 `기존 대상자에 반영 · 대상자 정보`·`새 대상자로 등록`·`이 행 제외`를 고른다. 방학 중식의 행 제외 제한은 유지한다. 기존 값과 다른 항목은 별도로 확인하므로 `덮어쓰기`로 표현하지 않는다. 값 충돌이 있을 때만 항목별 일괄 처리와 사람별 예외 수정 화면으로 이어진다.
- 가구가 자동 결정되면 가구 처리 선택을 제공하지 않고 기본 결정을 적용한다. 같은 핸드폰에 여러 기존 가구가 남아 있고 사용자가 신규 사람으로 추가하는 경우에만 `기존 가구 선택`을 표시한다. 기존 사람 연결·행 제외를 선택하면 가구 선택은 다시 숨기며, 실제 필요한 가구 선택을 해결하지 않은 채 저장하지 않는다.
- 기존 사람·가구와의 연결이 모호하면 선택이 필요한 항목만 보여준다. 자동 연결·신규 등록과 가구 묶기 규칙으로 결정된 행은 마지막 확인 목록에 표시하지 않는다. 해결하지 않은 충돌이나 취소는 명단을 저장하지 않는다.

## 방학 중식 명단 불러오기

- 기존 운영 명단이 있을 때 가져오기 방식에서 `방학 중식 대상자 갱신`을 선택할 수 있다. 최초 DB 명단 불러오기와 구분한다.
- 지정한 적용일부터 중식 명단에 있는 사람은 배송, 기존 중식 배송 대상자 중 명단에 없는 사람은 미배송으로 자동 갱신한다. 이후 명단 갱신 때까지 적용한다.
- 누락 대상자를 일일이 확인하게 하지 않는다. 정확히 일치하는 사람은 자동 연결하고 새 사람은 자동 등록한다. 사람 연결이 모호하거나 원본의 필수 행에 오류·제외가 있으면 작업자가 먼저 해결한다.
- 방학 중식은 이름과 대표 핸드폰의 숫자를 기준으로 연결한다. 생년월일은 연결 기준으로 사용하지 않는다. 원본의 행 묶음도 같은 기준을 사용한다. 핸드폰 누락·동명이인·중복 연결은 직접 확인하며 번호만 같은 다른 이름을 자동 연결하지 않는다. 일반 명단 불러오기의 연결 기준은 유지한다.
- 학교·학년은 학교 단계(초→중→고)를 먼저 비교하고 같은 단계에서는 높은 학년을 선택한다. 학교·학년은 함께 비교하며 낮은 단계로 되돌리지 않는다. 같은 단계의 서로 다른 학교명이나 판단할 수 없는 단계·학년은 직접 확인한다.
- 기존 대상자의 실제 값 충돌만 항목별로 일괄 처리하고 사람별 예외를 따로 수정한다. 사용자 칼럼과 중식 배송담당·순서도 같은 기준을 적용한다. 반영할 값은 가져온 값을 제안하되 원본 빈칸은 기존 값을 제안한다. 사용자가 반영할 값을 비우면 삭제하며 공통 배정에서 상속되는 배송담당·순서는 이 화면에서 비우지 못하도록 안내한다. 날짜·숫자·선택형을 검사하고 오류가 나면 입력을 유지한다.
- 자동 선택한 학교·학년은 검토 목록에서 제외하며, 실제 충돌이 없으면 별도 값 검토창을 띄우지 않는다. 취소하면 일부 값도 저장하지 않는다. 확인한 인적사항·사용자 칼럼·중식 배정·상태는 한 변경번호와 자동 백업으로 저장하며 조식·석식 가입·배정과 기존 가구는 유지한다. 결과에는 기존 배송 유지·배송 재개·신규·미배송 전환 인원수를 보여준다.

## 헤더 필터와 조식 설정 정리

- 열별 검색은 엑셀 필터처럼 각 열 제목 옆 버튼으로 통합한다. 헤더 아래 상시 검색행은 표시하지 않는다. 명단 상단 전체 검색창은 별도로 제공하며, 전체 검색과 헤더 필터를 함께 적용한다.
- 헤더 버튼의 팝업에서 검색·값 선택·전체 선택·필터 해제를 제공한다. 적용해야 반영하고 취소하면 이전 조건을 유지한다. 전체 선택 해제는 0행으로 표시한다.
- 열 제목 경계를 더블클릭해 너비를 자동 맞출 때 필터 버튼과 정렬 우선순위 표시 공간을 확보하고, 본문 값이 더 길면 본문에 맞춘다.
- 칼럼 검색어나 값 선택 필터가 적용돼 있으면 검색 영역 아래에 해당 칼럼 이름과 `칼럼 필터 해제`를 보여준다. 한 번에 칼럼 조건을 해제하고 저장하며, 전체 검색어·생일·보관함·조회 날짜 등 다른 조건은 유지한다. 재실행으로 복원된 필터와 전체 선택 해제로 0행이 된 경우도 안내한다.
- 필터가 적용된 열은 버튼에서 구분한다. 열 제목 클릭 정렬과 필터 버튼 동작을 분리하며, 열 이동·크기 변경·가로 스크롤에도 버튼 위치를 유지한다.
- 여러 칼럼을 함께 정렬할 수 있다. 먼저 선택한 칼럼부터 우선순위를 부여하며 각 칼럼은 클릭할 때마다 오름차순·내림차순·해제 순서로 바뀐다. 한 칼럼을 해제해도 다른 정렬은 유지하고, 다시 선택하면 마지막 우선순위로 추가한다. 모든 정렬을 해제하면 원래 명단 순서로 돌아간다. 헤더에 정렬 방향과 우선순위를 표시하고 필터 버튼과 겹치지 않게 한다.
- 별도 `조식 배송 규칙` 설정은 제공하지 않으며, 기존에 저장한 선택도 새 일일식수 계산에 적용하지 않는다. 기본 배송 일정과 날짜별 휴무·대체배송 설정을 사용한다. 과거 정책 이력은 삭제하지 않는다.

## 장기 미배송 보관함

- 대상자 테이블을 나누거나 행을 삭제하지 않고 일반 명단과 장기 미배송 보관함을 조회로 구분한다. 보관 여부는 배송·청구 계산이나 이력을 변경하지 않는다.
- 화면에서 선택한 조회 날짜를 기준으로 석식·조식·중식 모두 연속 미배송인 기간을 판단한다. 기준은 기본 365일이며 사용자가 변경할 수 있고 이 컴퓨터의 화면 설정으로 기억한다. 조회일을 포함한 최근 n일을 계산하며 개월 단위를 사용하지 않는다. 조회 날짜를 바꾸면 숨기기와 보관함을 바로 다시 계산한다.
- 1일 기준은 조회일의 세 식종 표시가 모두 `-`인 행을 바로 숨긴다. 중지·미가입 식종과 학교 일정상 중식 업체 제공 대상이 아닌 날은 명단에서 `-`로 표시하므로 숨기기에서는 배송 없음으로 취급한다. 반복 제공 요일·실제 배송요일과 배송 담당자의 지정 여부는 판정에 사용하지 않으며 가져온 다음 날까지 기다리게 하지 않는다.
- 2일 이상은 사용자에게 보이는 식종 변경 이력이 있으면 기간 안에 어느 가입 식종이든 배송 또는 일시중지 상태가 하루라도 있는지 기존 기간 규칙으로 판단한다. 사용자에게 보이는 식종 변경 이력이 전혀 없고 조회일의 세 식종 표시가 모두 `-`이면 기준 일수와 관계없이 보관한다. 일반 Excel 명단 불러오기로 만들어져 화면 이력에서 숨긴 가입·상태 기록도 이 경우에는 보이는 이력으로 간주하지 않는다. 현재 배송 또는 일시중지로 표시되는 식종이 있으면 이 예외를 적용하지 않는다.
- 기본 화면은 보관 대상을 숨긴 일반 명단이다. 상단에 명단 종류·보관 기준·보관 인원을 상시 표시하지 않는다. `더보기 → 명단 관리 → 장기 미배송 보관함`에서 조회를 전환하고, 보관함을 보는 동안에만 검색창 아래 칼럼 필터 안내 줄에 나타나는 `보관 기준 설정`에서 일수를 변경한다. `칼럼 필터 해제`와 같은 높이로 두고 바로 옆에 일반 명단으로 돌아가는 `나가기`를 둔다. 칼럼 필터가 없어도 보관함에서는 이 줄을 표시하며, 나가기는 검색·필터·조회 날짜·정렬을 유지한다. 보관함에서도 전체 검색·헤더 필터와 이력보기를 사용할 수 있다. 배송 재개나 상태 수정 후 조건을 충족하지 않으면 일반 명단에 자동으로 다시 표시한다.
- 보관 기준 설정 창에서 일수를 바꾸면 일반 명단과 보관함의 표시 대상을 즉시 미리 갱신한다. 저장하면 새 기준을 기억하고, 취소하거나 창을 닫으면 저장된 기준으로 명단을 되돌린다.
- 전체 검색창 옆 `숨긴 행 포함`을 선택하면 검색어 없이도 일반 명단에 장기 미배송 보관 대상까지 함께 표시한다. 해제하면 보관 대상은 다시 숨긴다. 선택 상태는 재실행 후에도 기억하며, 보관함 자체는 계속 보관 대상만 표시한다. 전체 검색·칼럼 필터 등 다른 조회 조건은 유지하고 칼럼 필터의 값 목록에도 표시 대상인 숨긴 행의 값을 포함한다.

## 식종별 배송 기본값

- 공휴일 대체식 제공일 표는 해당 공휴일에 실제 제공 예정인 식종만 입력받는다. 가입 기간과 개인·가구·공통 제공 요일을 적용하며, 원래 제공하지 않는 요일의 식종은 `—`로 표시한다. 조식처럼 제공일과 실제 배송일이 다른 묶음배송은 원래 제공일을 기준으로 포함한다.

- `설정 → 식종별 배송 기본값`에서 석식·조식·중식의 제공 요일과 요일별 실제 배송일을 지정한다. 운영 파일의 공통 설정으로 저장하며, 별도 지정이 없는 기존 대상자와 새 대상자 모두가 상속한다.
- 저장된 공통 설정이 없을 때 석식은 월~목 주 4회 당일 배송을 기본으로 한다. 중식은 월~금 중 학교 일정상 업체 제공 대상일에 제공하고, 조식은 금·토·일분을 금요일에 묶어 배송한다. 명시적으로 저장한 공통·개인·가구 설정은 유지한다.
- 개인·가구의 명시적인 별도 설정은 보존하고, 별도로 지정하지 않은 항목만 공통 기본값을 따른다. 개인 배송 설정의 초기화는 현재 운영 파일의 기본값을 사용한다. 기본값 상속만으로 `별도 설정만`에 포함하지 않는다.
- 저장 후 명단·일일식수·식수와 청구 계산이 같은 기본값을 사용한다. 월별 식수·청구서·확인서는 실제 배송일에 속한 식사 건수를 기준으로 하며 학교 급식 일정과 명시적인 휴무·대체식 규칙을 유지한다.
- 저장은 변경 이력과 기존 자동 백업 흐름을 따른다. 취소·변경 없음은 저장하지 않고, 재실행 후에도 저장값을 유지한다. 기존 이력의 상태를 재구성할 때는 해당 이력의 기본값을 사용한다.

## 개인별 배송 설정과 가구 전체 적용

- 기본 식종은 석식·조식·중식 세 가지를 유지한다. 각 사람의 식종별 제공 요일·배송요일·형태를 각각 지정한다. 기본 적용 범위는 선택한 한 사람이며, `같은 가구 전체에 적용`을 선택한 경우에만 가구원에게 함께 반영한다. 별도 지정 체크 없이 값을 직접 수정하고 기본값과의 차이로 별도 설정을 자동 판정한다. 별도 배송 형태는 `도시락`, `식재료 박스`처럼 직접 입력한다. 형태가 달라도 같은 식종의 급식·청구 기준을 사용한다.
- 별도 요일은 해당 식종의 제공 요일이다. 예를 들어 석식을 월~금으로 지정하면 주말 석식은 제공하지 않고 금요일에 주말분을 묶어 제공하지 않는다. 휴일·대체배송 규칙은 기존 흐름을 따른다.
- 선택 정보의 `정보 수정` 옆 `배송 설정`에서 선택한 사람의 전용 창을 연다. 개인 적용과 가구 전체 적용의 이름·인원을 구분해서 표시한다. 가구에 연결되지 않은 사람도 개인 설정을 수정할 수 있다. 사람 정보 수정창의 배송 설정도 개인 적용이 기본이다.
- 제공 요일과 배송요일은 위아래로 맞춰 배치하고 배송 형태는 바로 입력한다. 식종별 `초기화`와 `전체 초기화`로 기본값을 복원한다. `기본값`·`별도 설정`과 아직 저장하지 않은 변경을 구분한다.
- 기본값과 같아진 항목은 기본값 상속으로 처리한다. 단, 기존 명시적 설정을 열기만 하거나 값을 원래대로 돌린 경우에는 revision을 만들지 않는다. 저장·취소는 기존 revision 및 백업 흐름을 따른다.
- 명단 필터에는 `별도 설정만` 체크 하나를 둔다. 선택하면 개인에게 실제 적용되는 별도 설정이 있는 대상자만 표시하고 배송 설정 상세 열을 보여준다. 해제하면 상세 열을 숨긴다. 같은 가구라도 개인 설정이 다르면 각각 구분한다.


## 선택 정보의 식종 이력과 배송요일

- 오른쪽 선택 정보에는 성명·같은 가구·식종 변경 이력을 표시하고 연락처와 주소는 별도로 반복 표시하지 않는다. 명단의 연락처·주소 열과 정보 수정 기능은 유지한다.
- 오른쪽 선택 정보는 개인별 이력 창의 식종 변경 표와 같은 상태 기록만 최근 순으로 표시한다. 서로 다른 식종이나 상태 기록은 합치지 않는다.
- 선택 정보의 식종 변경 이력은 `식종 / 구분 / 기간`만 표시한다. 식종·구분을 첫 줄에 강조하고 기간을 별도 줄에 표시한다. 변경자·변경번호·적용일·사유·기록 시각은 선택 정보에 표시하지 않는다.
- `행 추가` 버튼으로 등록한 식종은 저장된 배송 시작일을 기준으로 `시작` 이력을 표시한다. 기존 행 추가 기록도 선택 정보와 개인별 식종 변경 이력에 함께 표시하며, 같은 기록에 명시적인 상태가 있으면 그 상태만 표시한다. 명단 불러오기와 일반 가입기간 수정은 이 규칙으로 시작 이력을 만들지 않는다.
- 개인별 이력의 식종 변경 표와 선택 기록 상세는 `식종 / 구분 / 기간 / 변경자 / 변경번호`의 5개 항목만 같은 순서로 표시한다. 구분은 `시작`·`중지`·`일시중지`로 표시하고, 기간은 일시중지일 때 `yyyy-mm-dd ~ yyyy-mm-dd`, 시작·중지일 때 `yyyy-mm-dd ~ `로 표시한다. 날짜가 없으면 미지정임을 밝힌다. 적용일·사유는 이 표와 선택 기록 상세에 표시하지 않으며 저장된 원본 이력은 유지한다. 가입기간·배송배정 등 다른 변경과 상태 기록 삭제는 전체 변경 이력에서 확인하도록 안내하고, 전체 변경 이력·Excel 내보내기는 유지한다.
- 개인별 이력의 정보 변경 표는 `항목 / 이전 값 / 변경 값 / 변경자 / 변경번호`, 민원 표는 `접수일시 / 식종 / 접수 경로 / 내용 / 기록자`를 표시한다. 정보 변경 탭 하단에는 별도 상세 설명 영역을 두지 않는다. 사용자 정의 값은 실제 값만 표시하며 `kind`·`value` 등 저장 형식을 노출하지 않는다. 민원 상세 영역에서는 나머지 날짜·사유 등 저장된 내용을 확인할 수 있으며 내부 ID와 반복되는 대상자 이름은 숨긴다. 긴 내용은 줄바꿈과 스크롤로 읽을 수 있게 한다.
- 개인별 이력의 상태 적용 기간 탭은 식종별 `기간 / 상태`를 최근 기간부터 보여준다. 기간을 선택하면 아래에서 관련 변경 시각·등록 상태·기간·원문 내용을 확인한다. 상태 계산과 전체 이력·내보내기 자료는 변경하지 않는다. 빈 이력에 기간을 임의로 만들지 않는다.
- 일반 `Excel 명단 불러오기`로 생성된 변경은 선택 정보·개인별 이력 창과 Excel 변경 이력 시트에 표시하지 않는다. 기존 기록과 새 기록에 동일하게 적용한다. 방학 중식 명단 갱신, 수동 수정, 민원은 표시한다. 가져온 명단과 저장된 revision은 그대로 유지한다.

- 선택 정보의 식종 변경 이력은 식종·구분을 먼저 보여주고 기간을 별도 줄로 표시한다. 내용은 한 줄 말줄임이나 툴팁에만 숨기지 않는다.
- 관할동 등록 이력의 이전 값은 해당 변경 직전 기록에서 적용일에 유효했던 관할동으로 표시한다. 새 저장 기록이라는 이유만으로 빈칸 처리하지 않으며, 변경번호가 다른 기록을 값이 같다는 이유로 합치거나 삭제하지 않는다.
- 기간은 개인별 이력의 식종 변경 표와 같은 값으로 표시한다. 시작일·일시중지 종료일이 없으면 미지정임을 명시하며 `종료일=;` 같은 내부 키·구분자 표현을 노출하지 않는다. 원본 이력 값은 변경하지 않는다.
- 같은 가구 목록은 불필요하게 빈 공간을 차지하지 않도록 하고, 이력에는 여러 줄을 읽을 수 있는 공간과 스크롤을 제공한다. 제목 옆 `전체 보기`에서 기존 상세 이력 창으로 이동한다.
- 사람 정보 수정창의 식종별 요일 체크 바로 아래에 `배송요일` 줄을 둔다. 식사를 제공하는 요일과 실제 배송하는 요일을 구분하고, 여러 날짜의 식사가 한 배송에 묶이는 관계를 설명한다.
- 조식 기본 제공 요일은 금·토·일이며, 세 날짜의 식사를 금요일에 묶어 배송한다. 묶음배송은 각 식사일당 1식씩 세고 배송일에 합산한다.
- 배송요일 설정도 개인 적용을 기본으로 하는 저장·취소·기본값 복원 흐름을 따른다. 휴무·대체식의 명시적인 날짜별 지정은 유지한다.


## 전체 변경 이력

- `더보기 → 이력·민원 → 전체 변경 이력`에서 최근에 저장한 변경번호부터 조회한다. 변경번호·사유·변경자로 검색하고, 변경번호를 선택하면 당시 바뀐 대상·식종·항목·내용을 함께 보여준다.
- 저장 기록 검색은 마지막 입력 후 0.5초 동안 추가 입력이 없을 때 적용한다. 입력 중에는 기존 결과를 유지하며, 창을 닫으면 대기 중인 검색을 취소한다. 목록은 처음 불러온 자료에서 검색하고 선택 기록의 상세 내용은 필요할 때 읽는다.
- 검색 결과가 바뀌어도 선택한 변경번호가 남아 있으면 선택과 이미 표시한 상세 내용을 유지한다. 다른 변경번호의 상세 내용은 창을 열어 둔 동안 제한된 범위에서 다시 사용하며, 검색 중 상세 내용을 읽은 뒤에는 사용자가 다른 창으로 이동하지 않은 경우에만 검색 입력 위치와 선택 영역을 복원한다.
- 전체 이력에는 일반 Excel 명단 불러오기와 운영 설정 변경도 포함한다. 개별 이력의 가져오기 표시 규칙은 유지한다.
- 동일하게 표시되는 변경번호가 있어도 각각의 저장 기록을 구분한다. 이력 조회는 현재 명단·설정·저장 기록을 변경하지 않는다.
- 내보내기 비밀번호 변경은 변경 사실만 표시하고 비밀번호 값은 표·상세 내용·툴팁에 노출하지 않는다.
- 전체 변경 이력의 대상·항목·변경 내용은 사용자가 이해할 수 있는 한국어로 표시한다. `meal.history_cancellation` 같은 내부 종류 이름이나 UUID를 그대로 노출하지 않는다. 식종 이력 취소는 `식종 변경 등록 취소`로 표시하고 대상자·식종·취소한 상태와 적용 기간을 안내한다. 아직 표시 규칙이 없는 항목은 내부 값 대신 `기타 변경`과 추가·수정·삭제 설명을 사용한다.
- 배송 처리와 함께 자동으로 가입 기간이 생기거나 늘어난 경우, 가입 기간 변경은 해당 배송 기록 안에 함께 표시한다. 개인별 가입 기록과 같은 가구의 합쳐진 배송 기록을 별도 행으로 중복 표시하지 않는다. 같은 가구라도 실제 변경 내용이나 적용 기간이 다르면 각각 표시하며 저장된 감사 기록은 유지한다.
- 변경 내용은 실무자가 쓰는 쉬운 말로 표시한다. 사람·항목과 바뀌기 전·후의 값을 구분하고, 여러 항목을 한 줄에 이어 붙이지 않는다. 내부 항목 이름·식별번호·저장 형식 대신 사용자가 알아볼 수 있는 이름과 설명을 사용한다.
- 목록에서는 어떤 작업을 저장했는지 먼저 읽을 수 있게 하고, 선택한 기록의 변경 내용을 넓은 공간에서 확인하게 한다. 기록 시각·변경자·변경번호는 보조 정보로 구분하며 기존 검색과 기록 선택·복구 기능을 유지한다.
- 상세 표는 `대상 | 항목 | 변경 내용` 세 칼럼으로 표시한다. 대상에는 이름만, 항목에는 명단의 실제 칼럼 이름을 표시하며 사용자가 바꾼 칼럼 이름도 반영한다. 여러 칼럼의 변경은 항목별 행으로 나눈다. 질문형 제목은 사용하지 않는다.
- 항목별 값은 `이전:`과 `이후:`로 표시하며 명단 행 추가도 같은 형식을 쓴다. 내부 기록 순서인 `position`은 표시하지 않는다. 빈 값의 저장 형식만 달라 실제 값이 그대로인 항목은 상세 표에서 제외하고, 식종과 해당 적용 기간은 한 행 안에서 함께 표시한다.
- 같은 가구에서 동일하게 바뀐 항목은 한 행으로 묶고, 대상 칸에 실제 변경된 사람의 이름을 한 줄씩 표시한다. 바뀌지 않은 가구원은 포함하지 않는다. 다른 가구이거나 변경 내용·적용 기간이 다르면 따로 표시한다.
- 상태 변경의 첫 줄은 `석식 중지`처럼 식종과 상태를 표시한다. 한 번 저장한 같은 대상자의 식종 변경은 상태·적용 기간·사유가 같을 때 `석식 · 중식 중지`처럼 가운데 점으로 묶고, 식종은 석식·조식·중식 순서로 표시한다. 기간·상태·사유가 다른 변경은 합치지 않는다. 같은 가구의 대상 이름을 묶을 때도 실제 변경된 식종과 내용이 모두 같아야 한다. `추가 · 상태:`나 추정한 이전 상태는 붙이지 않으며 적용 기간과 사유는 아래에 분리한다.
- 전체 변경 이력의 적용 기간은 `yyyy-mm-dd ~ yyyy-mm-dd`로 표시한다. 종료일이 없으면 `yyyy-mm-dd ~ `처럼 끝 날짜를 비우고, `종료일 미지정`·`계속` 같은 문구를 덧붙이지 않는다.

## 작업 중 진행 안내

- 구주소 업데이트의 처리 인원·전체 인원·진행률은 얇은 진행 막대 위의 별도 텍스트로 표시한다. 줄바꿈 가능한 공간을 확보해 글자가 잘리지 않게 하며 막대 내부에는 글자를 넣지 않는다.
- 예외 셀 지정·해제뿐 아니라 시간이 걸리는 저장·불러오기·명단 갱신에도 작업에 맞는 진행 안내 창을 표시한다. `예외 셀을 적용하는 중입니다`, `명단을 새로 불러오는 중입니다`처럼 현재 하는 일을 쉬운 말로 알려준다.
- 진행률을 알 수 없으면 움직이는 막대를 사용하며 임의의 백분율이나 완료 시간을 표시하지 않는다. 처리 중에도 창이 다시 그려지고 반응하도록 데이터 처리와 화면 갱신을 구분한다.
- 진행 중에는 중복 조작을 막고 Esc·닫기로 안내만 없애지 못하게 한다. 성공·실패 모두 안내 창을 닫은 뒤 결과나 오류를 표시한다. 저장 성공 후 자동 백업 실패는 저장 실패와 구분한다.
- 확인·입력 창은 진행 안내와 겹쳐 띄우지 않는다. 이미 진행 안내가 있는 작업에는 같은 안내를 중복해서 띄우지 않는다. 저장 후에는 조회일·검색·필터·정렬과 유효한 셀 선택을 유지한다.
- 청구서·확인서·일일식수는 자료 조회·급식 계산·Excel 생성·생성 기록 저장과 백업을 진행 안내 아래에서 처리한다. 청구서·확인서는 비밀번호를 적용하고, 일일식수는 공통 비밀번호 설정 여부와 관계없이 비밀번호 없이 만들며 비밀번호 설정 화면을 열지 않는다. 생성 후 파일 확인도 화면을 멈추지 않게 한다. 양식·기간·출력 위치 선택과 완료·실패 알림은 화면에서 처리하고, 실패를 완료로 표시하지 않는다.
- 문서 생성 완료창을 열 때 파일 확인 안내는 한 번만 표시한다. 새 문서를 만드는 동안 같은 이름의 파일이 생기면 덮어쓰지 않고 다시 생성하도록 안내한다. 생성 이력 저장에 실패해 파일을 정리할 때도 다른 내용으로 바뀐 파일은 남기고 확인을 요청한다. 사용자가 덮어쓰기를 확인하는 일반 Excel 내보내기는 기존 동작을 유지한다.

## 앱 전체 긴 글 표시

- 앱 전체의 표·목록·트리·열 제목·선택 상자 등에서 긴 글을 `…` 또는 `...`로 바꾸지 않는다. 원문을 유지하고 공간이 부족하면 영역 경계에서 그대로 잘려 보이게 한다. 기존 줄바꿈·스크롤·전체 내용 툴팁은 유지할 수 있다.
- 메뉴와 안내 문구에도 불필요한 말줄임표를 붙이지 않는다. 표시 규칙 변경으로 저장 데이터나 복사할 원문을 바꾸지 않는다.


## Excel DB 내보내기 표시

- 가입 식종별 배송담당이 한 사람 안에서 다르면 기존 식종별 `명단`과 한 사람 한 행의 `명단(통합)`을 함께 출력한다. 통합 시트에는 식종별 배송담당과 순서를 별도 열로 두고, 미가입자도 포함한다. 모두 같으면 통합 시트를 중복 생성하지 않는다.
- 표 제목은 각 시트의 첫 행에 두고, 내보내기 기준일·revision UUID·변경번호·시간대·행 형식은 마지막 `내보내기 정보` 시트에 한 번만 기록한다. 명단을 선택하지 않으면 행 형식은 기록하지 않는다.
- 명단 주소는 조회 기준일에 적용되는 도로명주소·상세주소만 출력한다. 변경 이력의 대상 종류와 추가·수정·삭제 작업은 읽기 쉬운 한국어로 표시한다.

## 출력 템플릿 칼럼 연결

- 명단을 가져온 뒤에도 `설정 → 출력 칼럼 연결`에서 출력 연결을 수정할 수 있다. 원본 Excel을 다시 가져오게 하지 않는다.
- 양식(급식·행복도시락)과 문서(청구서·확인서)를 선택하고 `템플릿 칼럼`에 넣을 `명단 항목`을 지정한다. 지원하는 표준 항목·사용자 항목을 실제 이름으로 보여준다.
- 연결을 선택할 수 있는 모든 템플릿 칼럼에 `1순위`와 `2순위` 선택칸을 제공한다. 대상자의 1순위 값이 없거나 빈 문자열·공백뿐일 때만 2순위 값을 사용한다. 두 값 모두 없으면 비우며, 숫자 0과 거짓 값은 빈 값으로 보지 않는다. 두 항목의 값을 합치지 않는다. 기존 연결은 1순위로 유지하고 2순위는 미선택으로 시작한다.
- 양식·문서별로 두 순위를 함께 저장·복원하며, 변경 감지·초기화·취소에도 두 순위를 모두 반영한다. 초기화는 1순위 기본 연결과 빈 2순위로 돌린다. 실제 청구서·확인서 출력과 확인서의 이름 표시에도 같은 우선순위를 적용한다.
- `명단 항목`은 현재 명단 칼럼의 표시 이름을 사용한다. 학교·주소·전화번호1·핸드폰1과 사용자가 바꾼 칼럼 이름을 반영하되 저장된 연결은 표시 이름과 독립된 항목 키로 유지한다. 같은 뜻의 이전 명칭은 선택 목록에 중복 나열하지 않는다. 기본 항목과 추가 항목의 이름이 같으면 구분 문구를 붙이고, 추가 항목 값이 기본 항목의 출력값을 덮어쓰지 않게 한다.
- 새로 연결할 명단 항목은 명단에 등록된 칼럼 중 문서 출력이 지원하는 칼럼만 보여준다. 청구서에는 자동 계산·식종 변경 이력·공통 제공기관·템플릿 값 유지도 함께 제공한다. 명단에 없는 항목을 가리키는 기본값·저장값은 `비움`으로 표시하고 저장 시 빈 연결로 반영한다. `기존 연결`이나 사용할 수 없는 항목을 선택지에 남기지 않는다. 초기화도 없는 항목은 `비움`으로 처리하며 취소는 저장하지 않는다. 왼쪽의 템플릿 칼럼 이름과 확인서 가구 묶음 처리는 변경하지 않는다.
- 청구서의 `연번 (자동 계산)`은 각 출력 시트의 대상자 순서대로 1부터 시작하는 숫자다. 청구 대상이 아닌 행을 제외한 뒤 빈 번호 없이 매긴다. 연번 출력 칼럼에 다른 항목을 연결하면 그 항목을 출력한다.
- 식수·청구금액·연번처럼 자동으로 생성하는 칼럼은 자동 계산을 기본 연결로 제공하고 명단 항목이나 비움으로 바꿀 수 있게 한다. 확인서의 도로명주소·관할동은 1순위·2순위 연결을 수정할 수 있다. 주소에는 연결한 값만 출력하고 상세주소를 자동으로 합치지 않으며, 상세주소는 별도 출력 대상으로 표시하지 않는다. DB 가구는 저장된 소속으로 묶고 연결한 관할동별로 시트를 나눈다. 같은 가구의 출력 주소·관할동이 다르면 대상자의 실제 성명·생년월일·학교와 서로 다른 항목·값을 안내하며 내부 가구 키나 추정 행 번호는 표시하지 않는다. 출력에 사용하지 않는 상세주소 차이는 생성 오류로 처리하지 않는다. DB 가구의 출력 연결이 모두 비면 해당 칸을 비우며, 빈 관할동의 시트 이름은 `기타`로 표시한다.
- 별도 지정 체크 없이 기본 연결과의 차이를 판정한다. 현재 양식·문서의 초기화와 저장·취소를 제공하며, 양식 전환 때 저장하지 않은 변경을 조용히 버리지 않는다.
- 청구서·확인서 항목 설정은 각 출력 칼럼의 `1순위`·`2순위`·연결 상태를 한 줄에 표시한다. `기본 연결`·`별도 연결` 상태는 두 선택칸 아래에 두지 않고 같은 행의 맨 오른쪽에 표시한다.
- 저장한 연결은 이후 새로 생성하는 문서에 적용한다. 기존 명단 값과 이미 만든 Excel은 변경하지 않는다. 연결 설정도 revision·자동 백업으로 보존하며 변경 없음과 취소는 기록을 만들지 않는다.
- 청구서의 `아동과의 관계`는 명단 항목을 직접 연결할 수 있게 한다. `계`는 식수 합계 자동 계산, `제공기관`은 공통 제공기관 설정을 기본으로 사용하며 둘 다 연결을 수정할 수 있다.

## 설정 화면 배치와 날짜 입력

- 설정 첫 화면의 모든 항목은 같은 너비의 반폭 카드로 두 열에 배치한다. 관련 항목은 용도별 제목 아래 모으고, 마지막 항목이 홀수여도 한 줄 전체로 늘리지 않는다. 작은 창에서도 스크롤로 모든 항목과 닫기 버튼에 접근할 수 있게 한다.
- 앱 전체 날짜·날짜와 시간 입력은 포커스 여부와 관계없이 마우스 휠로 값이 바뀌지 않게 한다. 키보드 입력과 달력에서 날짜를 선택하는 동작은 유지한다.

## 명단 화면 설정 기억

- 명단의 열 너비와 순서·표시 여부는 이 컴퓨터의 화면 설정으로 기억한다. `별도 설정만`을 켰을 때 나타나는 배송 설정 열의 너비도 다시 켰을 때 복원한다.
- 표준 칼럼은 필수 항목을 포함해 헤더 우클릭에서 화면 표시 이름을 바꿀 수 있다. 이름 변경은 이 컴퓨터의 현재 운영 파일에만 적용하며 내부 칼럼 키와 명단 데이터는 바꾸지 않는다. 빈 이름과 변경 없음·취소는 저장하지 않는다.
- 칼럼 표시 여부는 각 헤더의 우클릭 `숨기기`와 `숨기기 해제`에서 바꾼다. 성명을 포함해 모든 칼럼을 숨길 수 있으며, 모두 숨긴 상태에서도 `더보기 → 칼럼 설정 → 숨기기 해제`로 복구할 수 있다. 숨긴 칼럼 목록에는 사용자가 바꾼 표시 이름을 쓴다.
- 전체 검색어, `숨긴 행 포함`, `별도 설정만`, 헤더의 열별 검색어와 선택한 값은 창을 닫고 다시 열어도 복원한다. 헤더에서 전체 선택 해제한 상태는 빈 선택으로 유지하고, 필터 해제는 저장된 조건도 지운다.
- 검색 조건은 운영 파일별로 구분하고, 현재 명단에 없는 열은 적용하지 않는다. 저장된 선택 값이 현재 명단에 없더라도 해당 선택을 유지한다.

## 명단 시트

- 시트 추가 `+` 버튼은 마지막 시트 바로 옆에 둔다. 시트를 삭제하거나 이름을 바꿔도 빈 탭 너비가 남지 않게 하며, 시트가 많으면 탭 스크롤과 추가 버튼에 계속 접근할 수 있게 한다.

- 선택한 시트는 짙은 남색 배경·흰 글자·청록색 밑줄로 표시한다. 나머지 시트는 밝은 배경으로 구분하고, 선택 전환으로 탭 크기가 바뀌지 않게 한다.

- 명단 아래의 시트는 같은 대상자 데이터를 보여주는 화면 구성이다. 시트를 추가하거나 삭제해도 대상자와 변경 이력은 복제하거나 삭제하지 않는다.
- `+`에서 이름을 정해 시트를 추가하면 기본 열 구성을 표시한다. 시트 탭의 우클릭 메뉴에서 이름 바꾸기·시트 삭제를 제공하며 마지막 시트는 삭제할 수 없다. 추가한 시트의 표시 열은 각 칼럼 헤더의 우클릭 메뉴에서 조정한다.
- 시트별 열 표시 여부·순서·너비와 시트 이름·순서·현재 선택은 운영 파일별 PC 화면 설정으로 기억한다. 새 사용자 항목은 기본 `명단` 시트에 표시하고 이미 꾸민 다른 시트에는 자동으로 추가하지 않는다. `명단` 시트를 삭제했다면 남은 첫 시트가 새 항목의 기본 표시 대상이 된다.
- 날짜·검색·필터·정렬은 시트 사이에서 공유한다. 시트를 바꾸면 배치 수정에 쓰이던 셀 선택은 지워 숨긴 식종 셀이 수정 대상에 남지 않게 한다.


## 공통 경로 설정과 중복 실행

- 운영 DB·자동 백업·문서 출력 위치는 사용자가 직접 지정하고, 경로 설정만 실행 파일 옆 `data/settings.ini`에 공통으로 저장한다. 기존 DB·백업·출력 파일을 자동 이동하지 않는다. 기존 PC 경로는 INI가 없을 때 한 번만 가져오며 개인별 열·검색·필터 설정은 PC에 유지한다.
- 프로그램 폴더의 실행 잠금은 최초 설정·로그인부터 종료까지 유지한다. 다른 실행 폴더를 사용해도 같은 운영 DB에는 동시에 접근하지 못하게 한다. 사용 중이거나 공유 폴더 연결·권한 문제가 있으면 한국어로 안내하고 진행을 중단한다. 잠금 오류를 비밀번호 오류나 DB 손상으로 안내하지 않는다.
- 운영 위치 변경 후 새 DB도 창과 세션을 닫을 때까지 예약한다. 생성·복원 성공 뒤 경로 설정 저장에 실패하면 생성 파일 보존 여부를 분명히 안내하고 세션을 닫는다. 경로 설정 저장 실패를 완료로 표시하지 않는다.
- 남아 있는 `.lock` 파일은 정상이며 사용자에게 삭제를 요구하지 않는다. 같은 공유 폴더의 모든 사용자가 잠금 기능이 포함된 버전을 사용해야 한다.


## 식종별 순서 필터와 여러 셀 수정

- 명단의 순서 헤더 필터는 식종별 순서 체크 목록으로 조건을 조합한다. 특정 식종만 있는 경우를 위한 별도 선택 상자나 `다른 식종에는 순서 없음` 체크박스를 두지 않는다. 식종 목록은 명단의 식종 정의와 제공된 필터 값에서 구성한다.
- 서로 다른 식종의 조건은 **AND**로 적용한다. 중식 번호만 선택하면 중식 순서가 선택한 번호와 일치하고 석식·조식 순서는 모두 없는 사람을 표시한다. 두 식종의 번호를 선택하면 두 조건을 모두 만족해야 한다. 다른 열의 필터 조건도 함께 적용한다.
- 한 식종에서 선택한 번호들은 허용할 값의 목록이다. `1`과 `2`를 선택하면 해당 식종 순서가 둘 중 하나여야 한다. 식종 전체 체크는 해당 식종의 번호들을 선택하며 `(빈 값)`은 별도로 선택한다.
- `(빈 값)`은 해당 식종에 순서가 없다는 뜻이다. 번호와 함께 체크하면 그 번호이거나 순서가 없는 경우를 허용한다. 아무 값도 선택하지 않은 식종도 순서 없음 조건으로 적용한다. 미가입 식종이라도 명시적으로 남은 순서가 있으면 빈 값으로 보지 않는다.
- 모든 식종을 선택 해제하면 순서가 전부 없는 사람만 표시한다. 공통 순서가 남은 사람은 제외한다. `필터 해제`는 순서 유무를 제한하지 않고 전체를 표시한다. 현재 표시된 값을 모두 체크한 상태를 필터 해제로 바꾸지 않는다.
- 기존에 저장한 식종별 번호·순서 유무 조건에도 같은 AND 규칙을 적용한다. 검색·적용·취소를 제공하고, 현재 없는 저장 값도 유지한다. 이전 버전의 합쳐진 순서 문자열은 `이전 필터 (행 전체 일치)`로 구분해 정확히 일치하는 행만 허용한다.
- `001`과 `1`은 서로 다른 값이다. 순서는 숫자 기준으로 나열하되 원문을 유지한다. 목록을 접고 펼치는 동작만으로 선택을 바꾸지 않는다.
- Ctrl을 누르고 서로 다른 사람·가구의 식종 셀을 선택한 뒤 선택한 셀을 우클릭하면 메뉴의 배송·일시중지·중지가 선택한 식종 전체에 적용된다. 선택하지 않은 셀을 우클릭하면 그 셀만 대상으로 바뀐다. 가구 전체 적용은 별도 선택한 경우에만 실행한다.
- Ctrl로 여러 사람의 식종 셀을 선택한 뒤 우클릭해 `배송담당 변경`을 선택하면 등록 기사 한 명 또는 미지정을 고른 적용일부터 선택한 셀에만 반영한다. 주소·배송순서·선택하지 않은 셀과 적용일 뒤의 예약은 유지하며, 하나의 revision과 자동 백업으로 저장한다. 변경 없음과 취소는 저장하지 않는다.
- 배송순서관리는 기본으로 선택일의 명단 현재 상태가 `배송` 또는 `일시중지`인 식종만 표시한다. 중지·미가입·학교 일정이 없어 현재 상태가 없는 중식 등은 제외한다. 가입되어 정상 배송으로 판단되는 식종은 별도 상태 변경 이력이 없어도 포함하며, 반복 제공 요일과 실제 배송요일은 적용하지 않는다. 문서·배송·청구 계산의 실제 제공일 판단은 유지한다.
- 배송순서관리의 `숨긴 명단 포함`은 기본 해제 상태이며 장기 미배송 보관 대상자와 위에서 제외한 식종을 숨긴다. 선택하면 선택일에 가입했거나 식종별 배정이 있는 모든 식종과 보관 대상자를 함께 표시한다. 미래에 적용할 배정은 해당 적용일부터 반영하고 공통 배정만으로 미가입 식종을 만들지 않는다. 제외는 가구를 묶기 전에 사람·식종별로 적용해 숨긴 대상의 연락처·순서와 일괄 순서 수정 대상이 섞이지 않게 한다. 전환과 순서 저장 후에도 식종 분리·열 필터 상태를 유지한다.
- 저장 후 열린 배송순서관리와 명단을 함께 갱신하고 선택한 기사·열 필터·식종 분리 상태를 유지한다. 배송순서관리는 저장된 새 순서로 표시한다.

## 배송순서 입력 방식

- `설정 → 배송순서 입력 방식`은 청구서·확인서 양식과 독립된 운영 파일 설정이다. 기본값은 `식종별로 따로 입력`이며 설정을 바꾸는 것만으로 기존 배송순서를 다시 쓰지 않는다.
- `한 번 입력해 모든 식종에 적용`에서는 배송순서 수정창에 입력칸 하나를 둔다. 사용자가 새 값을 입력하고 저장한 경우에만 석식·조식·중식 순서를 한 revision으로 같은 값으로 저장하며 기존 배송담당은 유지한다.
- 통합 입력에서 현재 식종별 순서가 서로 다르면 식종 이름과 현재 값을 각각 보여주고 입력칸은 비워 둔다. 값을 입력하지 않은 채 저장하거나 취소하면 기존 식종별 값을 유지하고 revision을 만들지 않는다. `모든 식종 순서 비우기`를 누른 뒤 저장하면 세 식종의 순서를 지운다. 식종별 값이 같으면 현재 값을 한 번만 표시한다.
- `001` 같은 앞자리 0은 통합 입력에서도 그대로 보존한다. 배송순서관리의 표 안 순서 수정은 표시 행이 가리키는 기존 식종·가구원 범위에만 적용하며, 통합 입력 설정을 이유로 선택하지 않은 식종까지 자동 확장하지 않는다.

## 현재 명단 시트 Excel 내보내기

- `더보기 → 현재 시트 Excel 내보내기`는 선택한 명단 시트에서 화면에 보이는 칼럼만 사용한다. 사용자가 바꾼 칼럼 이름과 화면의 칼럼 순서, 검색·필터·정렬 결과의 행 순서, 셀에 표시된 문자열을 그대로 한 시트에 저장한다.
- `001` 같은 앞자리 0, 여러 줄 표시, `=`·`+`·`-`·`@`로 시작하는 값은 계산식이나 숫자로 바꾸지 않고 문자 그대로 보존한다. 행이 0개면 머리글만 저장할 수 있으며 표시 칼럼이 0개면 내보낼 수 없다고 안내한다.
- 현재 시트 내보내기도 설정된 생성 Excel 공통 비밀번호를 반드시 적용하고, 전체 DB Excel 내보내기의 덮어쓰기 확인과 원자적 파일 저장 규칙을 따른다. `DB 전체 Excel로 내보내기`의 전체 명단·민원·변경 이력 출력은 별도 기능으로 유지한다.

## 배송순서관리 Excel 내보내기

- 배송순서관리의 `Excel 내보내기`는 현재 화면에 표시된 칼럼과 행을 화면 순서 그대로 저장한다. 선택한 기사, 숨긴 명단 포함, 칼럼별 검색·값 선택, 식종별 분리 상태를 반영하며 결과가 0행이면 머리글만 저장한다.
- 셀의 줄바꿈과 `001` 같은 앞자리 0, `=`·`+`·`-`·`@`로 시작하는 값은 문자 그대로 보존한다. 현재 명단 시트 내보내기와 같은 생성 Excel 공통 비밀번호, 덮어쓰기 확인, 원자적 파일 저장 규칙을 사용한다.
- `기사·식종별 Excel 내보내기`는 한 통합 문서 안에 `기사-식종`별 시트를 만들고 각 시트의 행을 배송순서 숫자 기준으로 정렬한다. 식종별 실제 가구원·연락처·배송순서를 사용하며 빈 순서는 뒤에 둔다.
- 기사·식종별 내보내기는 선택한 기사와 `숨긴 명단 포함`을 원본 범위에 반영한다. 기본으로 배송·일시중지 식종만 내보내며 중지·현재 상태 없는 식종은 체크한 경우에만 포함한다. 대상 행이 없는 식종 시트는 만들지 않는다. 열 제목의 검색·값 선택, 식종별 분리 상태는 반영하지 않으며 기존 `Excel 내보내기`의 현재 화면 저장 동작은 유지한다.

## 가구 공용 칼럼

- 칼럼 제목 우클릭 또는 `더보기 → 가구 공용 설정`에서 항목별 공용 여부를 직접 켜고 끈다. 칼럼의 가구 공용 여부는 사용자가 직접 설정하며 기본값은 모두 해제다. 기본 항목과 사용자 추가 항목을 구분해 제한하지 않는다. 이 설정은 PC별 화면 설정이 아니라 운영 파일에 저장한다.
- 공용을 켤 때 같은 가구의 값이 모두 같으면 검토창 없이 설정만 저장한다. 일부 가구에 서로 다른 값이 있으면 그 가구만 검토창에 표시하며, 값이 같은 가구의 값과 날짜별 이력은 다시 쓰지 않는다. 검토창은 중복된 `가구원` 칼럼 없이 현재 개인별 값과 오른쪽 공용 입력칸을 표시한다. 현재 개인별 값은 한 셀 안에서 가구원마다 작은 굵은 이름 제목과 바로 아래 실제 값 셀을 한 묶음으로 두고 위에서 아래로 쌓는다. 이름 영역은 내용에 맞춰 좁게 표시하며, 여러 구성 항목은 이름 아래에서 각각 구분한다. 공용 값 입력칸은 오른쪽에 유지한다. 각 값 셀을 개별 선택해 Ctrl+C로 저장된 전체 평문을 복사할 수 있다. 공용 값 입력칸은 편집 중 일반적인 복사·붙여넣기와 여러 줄 메모 입력을 지원한다. 값이 서로 다르면 임의로 하나를 고르거나 합치지 않고 사용자가 공용 값을 정하게 한다. 빈 값으로 지우는 조작도 명시적으로 지원한다.
- 공용 칼럼은 표시에서 구분하며 내부 칼럼 키와 사용자가 정한 이름은 유지한다. 도로명주소·상세주소는 선택한 칼럼 하나만 설정한다. 배송순서처럼 한 칼럼에 여러 값이 있는 경우에는 구성 항목을 구분해 입력한다.
- 저장한 공용 값과 이후의 공용 칼럼 수정은 적용일의 같은 가구 중 해당 칼럼의 예외로 지정하지 않은 가구원에게 반영한다. 검색·필터로 화면에서 숨긴 가구원도 포함하며 다른 가구와 공용으로 지정하지 않은 값은 변경하지 않는다.
- 공용 해제는 현재 가구원별 값을 유지하고 이후 수정부터 개별 적용한다. 취소·검증 실패는 기존 값과 설정을 유지한다. 설정과 값의 변경은 한 번의 저장과 변경 이력·자동 백업으로 처리한다.
- 한 번에 입력한 같은 가구의 공용 값이 서로 충돌하면 저장하지 않고 공용 설정에서 값을 결정하도록 안내한다. 식종 공용 변경 시 미가입 가구원 때문에 상태를 함께 적용할 수 없는 경우에도 가입 상태를 임의로 바꾸지 않고 설정에서 먼저 결정하게 한다.
- 검토 표는 편집이 비활성화된 상태에서도 휠·스크롤바로 이동할 수 있다. 명시적인 줄바꿈과 공백 없는 긴 문자열을 모두 셀 너비에 맞춰 줄바꿈하며, 이름 제목과 값이 잘리지 않게 행 높이를 계산한다. 긴 메모가 한 화면보다 길어도 가로·세로를 픽셀 단위로 이동해 중간과 끝 내용을 읽을 수 있게 한다.

## 가구 공용 예외

- 명단의 공용 셀을 우클릭해 `공용 예외`를 체크하거나 해제한다. 해당 메뉴는 공용으로 설정된 칼럼의 셀에만 표시하며, 여러 셀을 선택했더라도 우클릭한 사람·칼럼 하나만 변경한다. 예외는 사람·칼럼 조합으로 운영 DB에 저장하며, 프로그램을 다시 열어도 유지한다. 새 예외는 명단의 공용 셀 우클릭으로 지정한다.
- 예외인 사람의 해당 값을 수정해도 다른 가구원에게 전파하지 않으며, 다른 가구원의 공용 값 수정으로 예외인 값을 덮어쓰지 않는다. 공용을 켤 때 값 비교와 통일 대상에서도 제외한다.
- 예외를 지정하거나 해제할 때 현재 값은 변경하지 않는다. 예외를 해제하면 이후 공용 값 수정부터 다시 함께 적용한다. 이 동작을 공용 예외 조작에서 안내한다.
- 도로명주소·상세주소의 예외는 각각 따로 지정한다. 배송순서·배송 설정·식종 상태도 기존 공용 칼럼 단위를 따른다.
- 공용 칼럼의 헤더 필터에는 `예외만 보기`를 제공한다. 선택하면 해당 칼럼에서 공용 예외로 지정된 행만 표시하며, 다른 검색·값 선택 조건과 함께 적용한다. 공용이 아닌 칼럼에는 표시하지 않는다. 공용을 해제하거나 예외 지정을 변경하면 결과를 즉시 갱신한다. 적용·취소·필터 해제를 지원하며 조건은 운영 파일별 PC 화면 설정에 저장한다. 공용을 해제하면 해당 예외 필터도 해제한다.
- 별도의 예외 칼럼 추가, 셀 간 연결·동기화, `설정 → 가구 공용 예외` 목록 화면은 제공하지 않는다. 원본 공용 셀의 우클릭 `공용 예외` 지정·해제는 유지한다.


## 초기 명단 적용일 정정

- `설정 → 초기 명단 적용일`에서 처음 가져온 명단의 적용일을 앞당길 수 있다. 처음 가져온 달의 1일을 제안하고, 적용 전 변경할 날짜와 대상 수·제외 사유를 보여준다.
- 처음 가져오기 기록으로 확인한 사람의 최초 식종 가입·가구 소속 시작일만 앞당긴다. 이후 추가한 사람, 삭제한 사람, 별도로 수정해 최초 구간을 확인할 수 없는 대상은 임의로 바꾸지 않는다. 기간의 종료일·이후 가입 구간·중지·일시중지·이사·기사 변경은 유지한다.
- 정정은 새 변경 이력과 자동 백업으로 저장하며 예전 기록을 고치지 않는다. 취소·변경 없음은 저장하지 않는다. 저장 후 명단과 배송 현황을 갱신하고, 최신 변경번호로 만드는 문서는 정정된 적용일을 사용한다. 과거 변경번호로 만드는 문서는 그 당시 기록을 유지한다.

## 배송 시작 전 날짜 조회

- 대상자는 최초 배송 시작일 이전 조회에도 일반 명단에 표시한다. 시작 전 식종 상태는 `-`로 표시하고 배송·청구·식종별 집계에 포함하지 않는다. 기존 중지·보관 및 사용자가 지정한 검색·필터는 유지한다.

## 칼럼 입력 제한

- 식종 외에 직접 입력하는 명단 칼럼은 제목 우클릭의 `입력 제한 설정…` 한 항목에서 형식과 선택적인 최대 글자 수를 설정한다. 제한 없음은 문자 종류를 제한하지 않는 텍스트이며, 전화번호는 앞자리 2~3자리·가운데 3~4자리·끝 4자리 숫자와 하이픈을 허용한다. `02-123-4567`, `02-1234-5678`, `031-123-4567`, `010-1234-5678`을 사용할 수 있으며 숫자만 입력한 `02` 번호도 두 자리 지역번호 뒤에 하이픈을 표시한다. 날짜는 실제 존재하는 `YYYY-MM-DD`를 허용한다. 전화번호·핸드폰은 처음에 전화번호 형식, 생년월일은 날짜 형식이다.
- 전화번호·날짜 입력칸은 숫자 입력과 형식이 붙은 값의 붙여넣기를 받아 하이픈을 자동 표시한다. 커서 이동·삭제·중간 수정이 가능하고 입력 중에는 미완성 값을 허용하며 저장할 때 형식을 검사한다. 생년월일은 제한 없음으로 설정해도 날짜 입력 동작과 날짜 값 저장을 유지한다.
- 입력 제한은 운영 파일에 변경 이력으로 저장하며 다시 열어도 유지한다. 취소·변경 없음은 새 변경번호를 만들지 않는다. 셀 수정·정보 수정·행 추가·순서 수정에 적용하며 비워도 되는 항목은 빈 값으로 저장할 수 있다. 기존 값이 규칙에 맞지 않아도 그 값을 바꾸지 않은 수정은 막지 않는다. 가져오기와 기존 값에는 소급 적용하지 않는다.
- 배송 설정처럼 직접 텍스트를 입력하지 않는 파생 칼럼과 선택 목록형 사용자 항목에는 메뉴를 비활성화하고 이유를 안내한다.
- 숫자형 사용자 항목은 최대 글자 수만 설정하고, 날짜형 사용자 항목은 제한 없음 또는 날짜 형식과 최대 글자 수를 설정한다. 기존 항목의 숫자·날짜 저장 형식은 유지한다.

## 월별 식수 통계

- 학교별 중식 일정이 없거나 해당 날짜가 검토된 일정 기간 밖이면 그 대상자·날짜의 중식은 0식으로 처리한다. 조식·석식과 일정이 있는 중식은 정상 집계하며, 잘못된 일정 자료 등 다른 오류는 그대로 안내한다.
- `더보기 → 통계 → 월별 식수`에서 선택한 달의 모든 날짜를 `일자 | 석식 | 조식 | 중식 | 합계`로 표시하고 마지막 행에 월 합계를 표시한다. 처음에는 명단 조회일의 달을 선택한다. 0식인 날짜도 표시한다.
- 식수는 화면 필터나 배송기사 지정 여부와 관계없이 전체 명단의 실제 배송일 기준으로 계산한다. 금요일에 묶어 배송한 주말 조식은 금요일에 끼니 수만큼 합산한다. 다른 달 비교용 배송은 해당 달에 섞지 않는다.
- 월을 바꾸거나 새로고침하면 최신 운영 데이터의 변경번호로 다시 계산한다. 조회 실패는 실패 이유를 보여주고 이전 달의 수치를 현재 달의 0식으로 표시하지 않는다. 통계 조회는 운영 데이터와 변경 이력을 수정하지 않는다.


## 월별 식종 변경 이력

- 표의 성명·식종·구분·적용 기간·변경자·변경번호 헤더에는 기존 열 필터 팝업을 사용한다. 검색·값 선택·전체 선택·필터 해제와 적용·취소를 제공하며 여러 열의 조건은 함께 만족하는 행만 표시한다. 값 목록은 해당 월의 전체 결과에서 만들고, 필터가 적용된 헤더와 필터 이름·조회 건수/전체 건수를 표시한다. `전체 필터 해제`로 조건을 한 번에 지운다. 월 변경·새로고침에도 검색·선택값과 명시적인 전체 선택 해제를 유지하며, 현재 달에 없는 선택값 때문에 결과가 없더라도 조건을 임의로 해제하지 않는다. 필터는 열린 창 안에서만 유지하며 운영 데이터는 변경하지 않는다.
- `더보기 → 이력·민원 → 월별 식종 변경 이력`에서 전체 명단의 배송·일시중지·중지 기록을 조회한다. 처음에는 명단 조회일의 달을 선택하고, 연월 변경·이전 달·다음 달·새로고침을 제공한다.
- 종료일 없는 배송·중지는 원래 적용 시작일이 속한 달에만 표시한다. `9/30 배송 ~ 종료일 없음`은 9월에만 표시하고, 이후 일시중지가 끝나 원래 배송이 다시 적용되는 구간도 별개의 시작 기록으로 추가하지 않는다. 식종의 배송 시작일을 사용하며 기록 입력일·행 삽입일로 대체하지 않는다.
- 종료일이 있는 기록은 실제 적용 기간과 선택한 달의 겹침으로 조회한다. 시작일과 종료일을 모두 포함하므로 `10/29 ~ 11/3 일시중지`는 10월과 11월에 모두 표시한다.
- 성명·식종·구분·적용 기간·변경자·변경번호만 표시하고 생년월일·학교 열은 두지 않는다. 취소되거나 이후 변경으로 적용되지 않는 구간은 제외한다. 일반 명단 불러오기와 취소·복원 기록의 표시 범위는 기존 개인 식종 이력의 규칙을 따른다.
- 명단의 현재 검색·필터에 관계없이 조회하며 월 변경·새로고침에는 최신 운영 자료를 읽는다. 조회는 운영 자료를 수정하지 않고, 빈 목록과 조회 실패를 구분하며 실패 시 이전 달 목록을 남기지 않는다.

## 기사 목록 순서

- `기사 관리`에서 기사 행의 순서를 드래그로 옮기고 `순서 저장`으로 확정한다. 드래그할 위치를 화면에 안내하고, 저장하지 않은 순서가 있으면 닫을 때 저장·버리기·취소를 선택할 수 있게 한다.
- 순서는 운영 파일에 저장해 다시 열거나 재실행해도 유지한다. 기사 이름·전화번호·배정은 순서 변경으로 바뀌지 않으며, 순서를 옮긴 뒤 수정해도 선택한 기사에게 적용한다.
- 기존 순서가 없는 운영 파일은 이전 정렬을 유지하며, 순서를 저장한 뒤 새로 등록한 기사는 끝에 추가한다. 저장된 기사 목록을 사용하는 선택 상자도 같은 순서를 따른다.

## 변경번호 복구와 분기

- `더보기 → 이력·민원 → 전체 변경 이력`에서 변경번호를 선택한 뒤 `선택한 변경번호로 복구·분기`를 연다. 새 분기 만들기가 기본이며 분기 이름만 입력한다. 같은 운영 DB에 저장하며 파일 복사·새 비밀번호·저장 위치 선택은 요구하지 않는다.
- 현재 사용 중인 분기를 표시하고 분기 선택 목록으로 각 분기의 변경 기록을 조회한다. 분기 시작점과 공유하는 분기 전 기록을 함께 보여주고 해당 기록도 복구·새 분기의 시작점으로 선택할 수 있다. 조회할 분기를 고르는 것만으로 사용 중인 분기를 바꾸지 않는다. `전체 분기 · 감사 기록`에서는 모든 저장·전환 기록을 확인한다.
- 새 분기를 만들면 선택한 변경번호의 명단·상태·운영 설정으로 바로 전환한다. 기존 분기의 작업은 보존하고 `이 분기로 전환`으로 마지막 저장 상태를 다시 연다. 분기끼리 합치지 않는다.
- 현재 분기 복구는 선택 시점의 명단·상태·운영 설정 전체를 새 변경번호로 저장하며 과거 기록을 삭제하지 않는다. 저장 전 작업 대상과 종료 여부를 확인하고 취소·변경 없음은 기록을 만들지 않는다.
- 복구·분기 생성·분기 전환 완료 후 종료하고 다음 실행에 전체 상태와 설정을 다시 읽는다. 전체 이력에는 `다른 운영 파일 열기` 버튼을 제공하지 않는다. 현재 사용 중인 파일 이름을 창 제목에 표시한다.

## 배송순서관리와 일일식수 기사 순서 (2026-10-22)

- 배송순서관리는 메인 상단 버튼 없이 `더보기 → 기사 관리 → 배송순서관리`에서 연다. 기사 선택 상자로 한 기사만 조회하며 등록 기사·기존 이름 배정·미지정은 구분한다. 배송기사·배송순서 칼럼은 이 화면에서 숨기고 주소는 도로명주소만 표시한다. 메인 명단의 배송순서 칼럼과 기존 수정 기능은 유지한다.
- 행번호 위 머리글은 `배송순서`로 표시한다. 기사 옆 식종 선택에서 `전체 식종`·`석식`·`조식`·`중식`을 고를 수 있다. 한 식종을 선택하면 그 식종의 가구 행만 표시하고 순서를 저장하며, 다른 식종과 기사 배정은 유지한다. 전체 식종으로 돌아가면 기존 분리·합치기 선택을 복원한다.
- 검색·열 필터를 유지한 채 행을 드래그할 수 있다. 필터로 보이는 행들의 기존 자리에 드래그한 순서를 끼워 넣고, 숨긴 행은 그 자리에 유지한다. 해당 식종의 전체 순서를 한 변경번호에 다시 매겨 중복 순서를 피한다. 배송순서 머리글은 명단 원본에 저장된 번호를 표시한다. 필터·식종 선택·분리 표시만으로 번호를 다시 매기지 않으며, 합친 행의 식종별 순서가 다르면 식종 이름과 번호를 함께 표시한다. 실패하면 저장 전 행 순서로 돌아가며 다른 창에서 변경된 자료는 덮어쓰지 않는다. `전체 필터 해제`는 선택한 기사와 식종을 유지한다.
- 같은 가구의 식종·가구원 중 배송담당이 하나라도 다르면 처음에는 식종별 분리, 모두 같으면 합친 행으로 표시한다. 매번 현재 배정으로 기본값을 정하고 `식종별 분리`·`분리 해제`는 유지한다. 기사 선택과 분리 전환은 저장된 순서 자체를 바꾸지 않는다.
- `기사 관리`에서 드래그해 저장한 기사 목록 순서는 일일식수 문서의 기사 표시 순서에도 적용한다. 기존 이름만 있는 기사는 등록 기사 뒤에 기존 이름순으로 표시한다.

## 월별 식수·청구 기준과 청구서 이력 (2026-10-22)

- 공휴일 후보는 검토해 저장하기 전까지 평소 요일과 배송 기본값대로 처리한다. 후보라는 이유만으로 제외하거나 배송을 앞당기지 않는다. 대체식 날짜 제안에서도 미검토 공휴일을 자동 휴무로 취급하지 않는다.
- 배송일을 미제공으로 지정하면 그날 묶어 배송할 식사를 함께 제외한다. 대체식을 지정하면 묶음 전체를 지정한 날에 배송한다. 개별 식사일에 따로 저장한 미제공·대체식과 가입·상태 조건은 유지한다. 예전 금요일 휴무의 목요일 자동 이동 규칙은 적용하지 않는다.
- 청구서·확인서·월별 식수는 같은 실제 배송 묶음을 사용한다. 2026년 10월 조식 기본값에서 10/9만 미제공이면 10/2·16·23·30에 3식씩 총 12식이다. 10/3은 별도 지정 없으면 제외하지 않는다.
- `설정 → 식수·청구서 설정`의 `이번 달에 묶어 배송하는 다음 달 식수 포함`은 기본 선택이다. 해제하면 월별 식수·청구서·확인서에서 다음 달 식사일을 제외한다. 일일식수는 실제 배송할 전체 식수를 유지하며 월별 식수 화면은 현재 포함 여부를 표시한다. 운영 파일 변경 이력과 함께 저장하고 과거 원본은 당시 설정을 사용한다.
- 같은 설정에서 급식·행복도시락 템플릿의 실제 칼럼 중 청구서 식종 변경 이력을 넣을 기본 위치를 각각 선택한다. `출력 안 함`도 선택할 수 있다. 출력 칼럼 연결에서 따로 저장한 연결이 있으면 해당 연결을 우선 적용한다.
- 청구서 비고는 기본으로 명단 비고를 복사하지 않는다. 이력 항목에는 선택한 원본 변경번호의 해당 기간 식종 변경 이력을 `석식: 10/29~ 중지`, `석식: 10/23~10/29 일시중지`처럼 줄별로 출력한다. 일반 명단 불러오기·취소·덮어쓴 이력은 기존 월별 식종 변경 이력 규칙대로 제외한다. 개인 비고가 필요하면 출력 칼럼 연결에서 명단의 비고를 직접 선택한다.
- 청구서 이력의 상태명은 `배송`·`중지`·`일시중지` 세 가지로만 표시한다. 시작·재개도 `석식: 10/23~ 배송`처럼 출력한다.

- 더보기의 모든 진입 항목에는 설명과 바로가기 링크를 제공한다. 설정은 `html/06-settings.html`에 문서·배송·식수·화면·데이터 관리의 4개 탭 순서로 21개 항목을 설명하고 실제 메뉴 목록과 대조해 누락을 확인한다. 마우스 기본 조작·화면 용어를 설명하는 별도 표는 두지 않는다.
- 현재 프로그램을 예시 명단으로 촬영한 화면과 실제 메뉴·버튼 이름을 사용한다. 실제 이용자 정보를 설명서에 넣지 않는다. 화면에는 확대 보기와 키보드 Esc 닫기를 제공한다.

## 청구서 자동 계산 칼럼 연결 (2026-10-26)

- 청구서 출력 칼럼은 연번·식수·합계·청구금액·제공기관·식종 변경 이력을 포함해 1순위·2순위를 수정할 수 있다. 기존 코드에서 계산하던 값과 공통 설정을 기본 연결로 제공하며, 사용자가 선택한 연결을 생성 과정에서 다시 덮어쓰지 않는다.
- 자동 계산 항목은 출력 칼럼 이름과 분리해 선택한다. 템플릿 칼럼이 바뀌면 설정창을 다시 열어 새 칼럼에 계산값·명단 항목·식종 변경 이력을 연결할 수 있다. 같은 경로의 템플릿을 교체해도 다시 읽는다.
- `비움`과 2순위 `사용 안 함`은 해당 칸을 비우며, `템플릿 값·수식 유지`는 양식의 값을 유지한다. 0은 빈 값으로 판단해 2순위로 넘기지 않는다. 식수 0의 기존 빈칸 출력은 유지한다.
- 자동 합계·금액은 사용자가 다른 값으로 바꾼 식수 칸을 참조해 잘못 계산하지 않는다. 자동 식수 칼럼을 옮기면 참조 위치를 함께 바꾸고, 필요한 식수 칼럼이 없으면 계산된 식수·금액을 직접 출력한다. 기간 중 단가가 바뀐 경우의 정확한 금액도 유지한다.
- `이 문서 초기화`는 현재 양식·문서의 기본 연결과 빈 2순위로 되돌린다. 저장해야 적용하며 취소하면 기존 설정을 유지한다.

## 배포 사용자용 AI 설명서와 질문 찾아보기 (2026-10-29)

- HTML 설명서와 `AI_사용설명서.txt`는 같은 사용자 기능을 안내한다. AI용 파일은 코드·추가 문서 없이 챗봇에 한 번 첨부해 사용하는 단일 파일이며, 개발 지침은 `AGENTS.md`에 분리한다.
- 사용자가 하고 싶은 일로 찾을 수 있도록 질문별 본문 연결을 시작 페이지에 제공한다. 각 기능은 진입 위치·조작 순서·저장 후 확인·영향 범위와 예외를 설명한다.
- HTML 본문과 `docs/manual-intents.json`을 갱신한 뒤 `python scripts/export_ai_manual.py`로 AI용 전체 본문과 양쪽 질문 목차를 함께 갱신한다.
- 현재 화면의 메뉴 이름을 사용한다. 과거 화면 예시가 남아 있으면 촬영 범위와 본문 우선 안내를 표시한다. 내부에만 존재하고 사용자 진입 경로가 없는 기능은 사용 가능한 메뉴로 설명하지 않는다.


## 가구 묶기 기준 선택과 복구 후 식종 이력 (2026-10-29)

- `설정 → 데이터 관리 → 가구 묶기 기준`에서 기본 인적사항·주소·사용자 칼럼을 여러 개 선택한다. 기본은 핸드폰이며 선택한 칼럼 값이 모두 같은 경우에만 묶는다. 선택값 중 빈칸이 있으면 묶지 않고 핸드폰·전화번호는 하이픈·공백을 무시한다. 도로명주소·상세주소는 각각 선택한다. 식종·순서 등 계산·배정 칼럼은 기준 목록에 넣지 않는다.
- `저장·기존 명단에 적용`은 전체 명단을 확인해 기준값이 같으면 합치고 다르면 별도 가구로 나눈다. 합칠 가구 수와 별도 가구로 나눌 대상 수를 미리 표시하며 적용일 입력 없이 즉시 반영한다. 이전 구성은 변경 이력에 보존하고 개인별 배송 동작은 유지한다.
- 저장한 기준은 번호에 한정하지 않고 명단 불러오기·직접 행 추가·기준 칼럼 수정에도 적용한다. 공용 칼럼 설정·개인 예외와 가구를 묶는 기준은 별개다. 공용 값 충돌은 기존 확인창을 거쳐 기준·가구 소속·공용 값을 한 변경번호와 백업으로 저장하고, 중간 취소는 모두 저장하지 않는다. 동일 기준으로 다시 적용해도 기존 미통합 가구를 확인하며 아무 변경도 없으면 기록을 만들지 않는다.
- 변경번호 복구 후에는 복구 시점 이후의 식종 변경을 선택 정보·개인 이력·월별 이력·청구서 이력에서 제외한다. 전체 감사 이력은 보존하며 해당 기록이 있던 시점으로 다시 복구하면 식종 이력도 복원한다. 기록 시각이 같아도 저장 연결과 복구 대상에 따라 판정한다.
