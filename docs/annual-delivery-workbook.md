# 연간 배송 Excel 형식

프로그램은 **연도별 Excel 파일 하나**를 단일 원본으로 사용한다. 워크북에는 `명단` 시트 하나만 두며, 개인정보와 식종별 배송현황을 같은 표에 입력한다. `배송현황`, `접수장`, `배송정보`, `배송휴무`, Power Query 출력 시트와 별도 공휴일 목록은 사용하지 않는다.

## 필수 시트와 표준 헤더

워크북의 시트는 정확히 하나여야 하며 이름은 `명단`이다. 첫 행은 헤더다.

표준 헤더 순서는 다음과 같다.

```text
취학유형 | 학교명 | 학년 | 성명 | 생년월일 | 세대주 성명 | 아동과의 관계 |
관할동 | 도로명주소 | 상세주소 | 전화번호 | 핸드폰 | 제공기관 | 비고 |
식종 | 배송담당 | 연번 | YYYYMMDD ...
```

- 앞의 14개 열은 기존 명단의 인적사항에서 `ID`만 제외한 것이다.
- Excel 파일에서는 표시 편의를 위해 `세대주\n성명`, `아동과의\n관계`처럼 헤더 셀 안에 줄바꿈을 넣어도 된다. 프로그램은 이를 각각 `세대주 성명`, `아동과의 관계`로 정규화한다.
- `식종 | 배송담당 | 연번`은 순서와 인접성을 지켜야 하는 고정 열이다.
- 고정 열 오른쪽에는 날짜 열만 둘 수 있다.
- `ID` 열은 사용하지 않으며, `ID` 헤더가 있으면 새 계약 위반으로 로드가 거부된다.

## 한 사람을 나타내는 3행

한 사람은 빈 행 없이 **연속된 3행**으로 나타낸다.

- 세 행에는 `조식`, `중식`, `석식`이 각각 정확히 한 번씩 있어야 한다.
- 세 식종의 물리적 순서는 자유다. 운영 파일은 찾기 쉽도록 `조식 → 중식 → 석식` 순서를 권장하며 `assets/db2.xlsx`도 이 순서를 사용한다.
- `식종` 왼쪽의 모든 인적사항은 세 행에 같은 값으로 반복 입력해야 한다. 일부 행만 비우거나 서로 다른 값을 넣을 수 없다.
- 사람을 식별하는 별도 PK는 없다. 프로그램은 연속된 3행 묶음과 그 시작 행을 하나의 `RosterEntry`로 취급한다. 따라서 행 사이에 빈 행을 넣거나 한 사람의 세 행을 서로 떨어뜨리면 안 된다.
- 같은 성명이 있을 수 있으므로 성명은 일반 계약에서 PK가 아니다. 테스트 fixture는 가상 성명이 모두 달라 성명으로 해당 `RosterEntry`를 찾는다.

예시:

| 성명 | 관할동 | 도로명주소 | 상세주소 | 식종 | 배송담당 | 연번 | 20260728 | 20260729 |
|---|---|---|---|---|---|---|---:|---:|
| 홍길동 | 정자동 | 성남대로 1 | 101호 | 조식 | 기사A | 001 | 1 | |
| 홍길동 | 정자동 | 성남대로 1 | 101호 | 중식 | 기사A | 001 | 0 | |
| 홍길동 | 정자동 | 성남대로 1 | 101호 | 석식 | 기사A | 001 | | |

## 고정 열 규칙

### `식종`

허용값은 `조식`, `중식`, `석식`뿐이다. 각 사람의 3행 안에서 중복이나 누락이 없어야 한다.

### `배송담당`

해당 사람·식종 행의 배송 담당자다. 실제 배송 값이 `1`인 행을 리포트나 배송대타에 사용할 때는 빈칸일 수 없다.

### `연번`

담당자 안에서 같은 배송지를 묶고 정렬하는 값이다.

- 같은 가구 구성원은 같은 배송담당과 연번을 사용한다.
- 선행 0을 보존하기 위해 Excel 셀을 **텍스트 형식**으로 입력한다. 예: `001`.
- 배송리포트와 확인서 템플릿은 한 가구 최대 5명까지 지원한다. 같은 배송지에 6명 이상이 묶이면 누락을 막기 위해 생성을 중단한다.

### 주소 처리

- 확인서는 `관할동 + 도로명주소 + 상세주소`가 같은 사람만 한 가구로 묶는다.
- 같은 도로명주소라도 `101호`, `102호`처럼 상세주소가 다르면 서로 다른 가구다.
- 확인서와 주소 열이 있는 청구서에는 `도로명주소`와 `상세주소`를 공백 하나로 합친 전체 주소를 출력한다.
- `도로명주소`가 빈 대상자는 서로 다른 가구가 합쳐지는 것을 막기 위해 확인서 생성을 중단한다. `상세주소`는 비어 있어도 된다.

## 날짜 헤더와 배송 값

날짜 헤더는 `YYYYMMDD` 형식이다. Excel의 실제 날짜 셀도 읽을 수 있지만 표시와 관리 편의를 위해 문자열 `YYYYMMDD`를 권장한다.

| 셀 값 | 의미 |
|---|---|
| 숫자 `1` | 배송함 |
| 숫자 `0` | 일시중지 |
| 빈칸 | 중지 또는 전역 미입력/비배송 상태 |

문자열 `"1"`, 문자열 `"0"`, `O`, `X`, 상태 문자열은 허용하지 않는다. 배송 셀에는 수식을 사용할 수 없으며 `=1`, `=0`, `=""`도 로드 단계에서 거부한다.

빈칸은 열 전체의 상태를 먼저 판정한 뒤 해석한다.

- 해당 월의 모든 날짜 셀이 전체 21행 등 모든 배송행에서 빈칸이면 그 월은 **미입력** 상태다. 청구서를 만들 수 없다.
- 특정 날짜 열 전체가 빈칸이면 공휴일 또는 전체 비배송일이다. 배송리포트와 배송대타에서 제외한다.
- 입력된 날짜에서 특정 사람·식종 행만 빈칸이면 그 행은 **중지**다.
- 날짜 열에 `0`만 있으면 입력된 날짜지만 실제 배송 대상은 없다.

월 데이터를 전부 작성한 뒤 프로그램을 실행하는 운영 방식을 전제로 한다. 별도 완료 플래그나 자동 `1` 채우기는 사용하지 않는다.

## Excel 사용성 규칙

배포용 워크북은 다음 편집 보조 기능을 유지한다.

- `식종` 셀: `조식, 중식, 석식` 목록 유효성 검사
- 날짜 셀: 숫자 `0`, 숫자 `1`, 빈칸만 허용하는 유효성 검사
- 날짜 값 `1`: 초록색 조건부서식
- 날짜 값 `0`: 노란색 조건부서식
- `연번`: 텍스트 서식
- 첫 행과 날짜 왼쪽 고정 열 고정, 전체 표 자동 필터
- ID 관련 열과 유효성 검사는 두지 않음

## 새 월 추가

1. `연번` 오른쪽에 새 날짜 열들을 삽입한다.
2. 날짜 헤더를 `YYYYMMDD`로 입력한다.
3. 모든 사람의 조식·중식·석식 행 상태를 작성한 뒤 프로그램을 실행한다.
4. 공휴일이나 전체 비배송일은 해당 날짜 열 전체를 비운다.

새 월을 왼쪽에 삽입해 기존 월이 오른쪽으로 밀려도 된다. 프로그램은 물리적 열 순서가 아니라 헤더의 실제 날짜를 파싱해 정렬한다.

## 연도 변경

- 새 연도에는 새 파일을 만든다.
- 한 파일의 날짜 헤더는 모두 같은 연도여야 한다.
- 서로 다른 연도의 날짜가 섞이면 파일 로드가 거부된다.

## 도메인 조회 API

로드 결과에서 `RosterEntry`가 사람 객체다. 배송행은 ID 문자열 대신 같은 객체를 `DeliveryRow.person`으로 직접 참조한다.

- `book.rows_by_person[person]`: 그 사람의 식종별 배송행
- `book.get_delivery_row(person, meal)`: 사람 객체와 식종으로 한 행 조회
- `book.raw_delivery_value(person, meal, day)`: 원시 `1`/`0`/빈칸 상태 조회
- `book.effective_delivery_state(person, meal, day)`: 월·일 전역 상태까지 반영한 의미 조회
- `book.monthly_delivery_count(person, meal, year, month)`: 월 배송 횟수 조회

워크북에서 얻지 않은 별도 `RosterEntry`나 성명 문자열을 이 API의 사람 키로 넘기지 않는다.

## 파일 선택 시 검증 항목

- 워크북에 `명단` 시트 하나만 있는지
- `ID` 없이 인적사항 뒤에 `식종 | 배송담당 | 연번`이 연속하는지
- `연번` 오른쪽 헤더가 모두 유효한 날짜이고 중복·혼합 연도가 없는지
- 데이터 행 수가 3의 배수이고 각 사람의 3행이 연속하는지
- 한 사람의 세 행에서 모든 인적사항이 같은지
- 각 3행에 조식·중식·석식이 정확히 한 번씩 있는지
- 배송 셀 값이 숫자 `1`, 숫자 `0`, 빈칸 중 하나이며 수식이 아닌지

ID의 빈칸·중복·외래키 유효성은 더 이상 검사하지 않는다.

## 테스트 fixture

`assets/db2.xlsx`는 실제 개인정보가 없는 단일 시트 테스트 파일이다.

- 가상 명단 7명 × 조식·중식·석식 3행 = 21행
- 각 사람의 인적사항을 세 행에 반복하고 식종은 `조식 → 중식 → 석식` 순서로 배치
- 기존에 없던 식종 행의 일반 날짜는 빈칸으로 추가
- `2026년 6월·7월`은 기존 입력값이 남아 입력 완료 상태
- `2026년 8월`은 전체 빈칸으로 미입력 월 테스트
- `20260729`는 전체 빈칸으로 전체 비배송일 테스트
- `20260730`은 새로 추가한 행까지 전체 숫자 `0`으로 입력됐지만 배송 대상이 없는 날짜 테스트
- `20260728`은 숫자 `1`, 숫자 `0`, 개별 빈칸을 함께 넣어 배송·일시중지·중지를 구분
- `기사A`, `기사B` 복수 담당자와 같은 가구의 동일 담당자·연번으로 가구 묶음 테스트
- 식종/배송값 유효성 검사, `1`/`0` 조건부서식, 텍스트 연번을 포함

프로그램 상단에서 `assets/db2.xlsx`를 선택하면 새 단일 시트 계약을 바로 검증할 수 있다.
