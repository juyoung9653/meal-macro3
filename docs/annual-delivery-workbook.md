# 연간 배송 Excel 형식

프로그램은 사용자가 선택한 Excel 파일 하나를 단일 원본으로 사용한다. 선택한 워크북에서 이름이 `db`인 Excel 구조화 테이블을 찾아 개인정보와 식종별 배송현황을 읽는다. 테이블이 있는 시트의 이름과 위치는 자유이며, 다른 시트와 `db` 테이블 범위 밖의 셀은 읽지 않는다. 날짜 헤더에 여러 연도가 있으면 **DB 가져오기 설정** 창에서 이번 작업에 사용할 연도를 선택한다.

## 필수 테이블과 표준 헤더

워크북에는 이름이 `db`인 Excel 표(삽입 → 표)가 반드시 하나 있어야 한다. `db_backup`처럼 이름이 비슷한 다른 테이블은 읽지 않는다. `db` 테이블의 첫 행은 헤더이며, 헤더와 데이터 행은 모두 테이블 범위 안에 포함되어야 한다.

기본 헤더 순서는 다음과 같다.

```text
취학유형 | 학교명 | 학년 | 성명 | 생년월일 | 세대주 성명 | 아동과의 관계 |
관할동 | 도로명주소 | 상세주소 | 전화번호 | 핸드폰 | 제공기관 | 비고 |
식종 | 배송담당 | 연번 | YYYYMMDD ...
```

- 앞의 열은 프로그램이 사용하는 13개 인적사항과 업무용 `비고`다.
- Excel 파일에서는 표시 편의를 위해 `세대주\n성명`, `아동과의\n관계`처럼 헤더 셀 안에 줄바꿈을 넣어도 된다. 프로그램은 이를 각각 `세대주 성명`, `아동과의 관계`로 정규화한다.
- `식종`과 `배송담당`은 필수 역할이고 `연번`(배송 순번)은 선택 역할이다. 실제 헤더명과 관계없이 파일 선택 직후 표시되는 **DB 가져오기 설정** 창에서 해당 Excel 헤더를 직접 선택한다. 정확한 `식종` 헤더가 없더라도 이름에 `식종`이 들어간 헤더가 하나뿐이면 자동 선택하며, 후보가 여러 개면 사용자가 직접 고른다.
- 13개 표준 인적사항과 업무용 `비고`도 같은 창에서 각각 필수로 매핑한다. 두 청구서 템플릿에서 이 필드들을 사용하며 확인서도 성명·세대주·연락처·관할동·주소·비고를 사용한다. 선택한 원본 헤더는 `성명`, `학교명`, `도로명주소` 같은 프로그램 표준 필드로 변환되므로 청구서·확인서·배송 기능이 원본 헤더명을 하드코딩하지 않는다.
- 모든 매핑 열의 위치와 물리적 순서는 자유이며 서로 떨어져 있어도 된다. **사용 안 함**을 선택할 수 있는 필드는 배송 순번뿐이다. 필수 표시는 헤더 연결이 필요하다는 뜻이며 각 사람의 비고·상세주소 같은 개별 셀은 빈칸일 수 있다.
- 날짜 열도 위치와 순서가 자유롭다. 프로그램은 `YYYYMMDD` 헤더를 날짜로 식별하고 실제 날짜 순으로 정렬한다.
- 선택한 연도의 날짜 열만 배송 데이터로 읽고 다른 연도의 날짜 열은 무시한다.
- 매핑한 13개 인적사항과 `비고`만 명단 데이터로 읽는다. `8월SUM` 같은 월 합계·수식 열과 그 밖의 미매핑 열은 인적사항 비교와 가져오기에서 제외한다.
- `ID`, `8월SUM` 같은 미매핑 열은 있어도 된다. 프로그램은 삭제를 요구하지 않고 가져오지 않는다.

## 사람과 식종 행을 구분하는 방식

기본적으로 데이터 한 행은 한 사람의 한 식종을 나타낸다. 동일인은 기존 VBA와 같이 **성명 + 관할동 + (생년월일 앞 6자리 또는 핸드폰)** 조합으로 판정한다.

- 한 사람이 한 식종만 이용하면 한 행만 입력한다. 조식·중식·석식을 전부 입력할 필요가 없다.
- 한 사람이 여러 식종을 이용하면 각 행에 같은 성명과 관할동을 입력하고, 생년월일 앞 6자리 또는 핸드폰 중 하나가 같아야 한다. 행이 연속하지 않거나 중간에 다른 사람·빈 행이 있어도 동일한 키를 찾으면 한 사람으로 묶는다.
- 성명과 관할동은 앞뒤·중복 공백과 대소문자 차이를 무시한다. 생년월일은 Excel 날짜, `YYYYMMDD` 숫자, `YYYY-MM-DD`처럼 구분자가 있는 날짜 문자열을 정규화한 뒤 앞 6자리만 동일인 키와 인적사항 불일치 비교에 사용한다. 생년월일 열에 주민번호가 들어 있어도 뒤 7자리는 비교하지 않는다. 핸드폰은 하이픈 등 표시 차이를 제거해 비교한다.
- 성명과 관할동이 같으면 생년월일 키가 같거나 핸드폰 키가 같은 경우 동일인으로 합친다. 생년월일이 달라도 핸드폰이 같으면 합칠 수 있고, 핸드폰이 달라도 생년월일 키가 같으면 합칠 수 있다.
- 같은 사람의 일반 인적사항은 모든 해당 행에서 처음 나온 비어 있지 않은 값으로 자동 보완한다. 이후 행에 서로 다른 비어 있지 않은 값이 있으면 첫 값을 사용하되, 임의로 숨기지 않고 생성한 청구서의 `DB검토` 시트에 원본 행과 값들을 기록한다.
- 같은 사람 안에 같은 식종 행이 여러 번 있어도 파일을 거부하지 않는다. 날짜별로 어느 행이든 숫자 `1`이면 한 번의 배송으로 합치고, 배송담당과 순번은 먼저 나온 비어 있지 않은 값을 사용한다.
- 성명이 비었거나 생년월일과 핸드폰이 모두 비어 있으면 다른 행과 자동 병합하지 않는다. 관할동이 다르거나 한쪽만 비어 있어도 VBA 키가 다르므로 별도 사람으로 읽는다.
- 도로명주소와 상세주소는 동일인 판정에 사용하지 않는다. 같은 사람으로 합쳐진 행의 주소가 달라도 주소 차이 자체는 `DB검토` 항목에 기록하지 않고 처음 나온 비어 있지 않은 값을 사용한다.
- `비고`는 사람 동일성 판정에서 제외한다. 같은 사람의 식종별 행마다 달라도 되며, 비어 있지 않은 고유 내용을 줄바꿈으로 합쳐 청구서와 확인서에 사용한다.
- 매핑한 인적사항·식종·배송 열과 선택 연도 날짜가 모두 빈 행은 사람으로 읽지 않는다. 따라서 테이블 끝에 미매핑 합계 수식만 자동 채워진 행이 있어도 무시한다.

예시:

| 성명 | 관할동 | 도로명주소 | 상세주소 | 식종 | 배송담당 | 연번 | 20260728 | 20260729 |
|---|---|---|---|---|---|---|---:|---:|
| 김아침 | 정자동 | 성남대로 1 | 101호 | 조식(금요일) | 기사A | 001 | 1 | |
| 이저녁 | 야탑동 | 성남대로 2 | 201호 | 석식(월,화,수,목) | 기사B | 002 | 1 | |
| 박점심 | 서현동 | 성남대로 3 | 301호 | 2025_겨울중식(월,화,수,목,금) | 기사C | 003 | 1 | |

위 세 행은 성명이 모두 다르므로 세 사람이며, 각 사람은 자신에게 적힌 식종 행 하나만 가진다.

### DB검토 시트

VBA 동일인 키로 합친 행에서 학교명, 세대주 성명 등 일반 인적사항의 비어 있지 않은 값이 서로 다르면 청구서 생성은 중단하지 않는다. 프로그램은 첫 비어 있지 않은 값을 청구서와 확인서에 사용하고 생성된 청구서에 `DB검토` 시트를 추가한다.

`DB검토` 시트에는 성명, 생년월일, 핸드폰, 원본 행, 불일치 항목, 자동 선택값, 원본별 값을 기록한다. 핸드폰과 도로명주소·관할동·상세주소 차이는 검토 항목에 기록하지 않는다. 빈칸을 다른 행의 값으로 보완한 경우도 충돌이 아니다. 충돌이 없으면 이 시트를 만들지 않는다. 원본 DB 파일은 읽기 전용으로 사용하므로 자동 병합 결과가 원본 셀을 덮어쓰지는 않는다.

학년처럼 숫자로 입력할 수 있는 인적사항은 Excel 숫자 `1`, 문자열 `"1"`, 숫자 `1.0`을 같은 값으로 비교한다. 화면에 같은 값으로 보이는 셀을 자료형 차이만으로 `DB검토`에 기록하지 않는다.

## 매핑 역할 규칙

### `식종`

각 셀에서 `조식`, `중식`, `석식`을 부분 일치로 찾는다. 예를 들어 `조식(금요일)`, `석식(월,화,수,목)`, `2025_겨울중식(월,화,수,목,금)`은 각각 `조식`, `석식`, `중식`으로 읽는다. 한 셀에 표준 식종이 없거나 둘 이상 들어가면 모호하므로 거부한다. 한 사람에게 없는 식종은 정상이며, 같은 식종 행이 중복되면 날짜별 배송 여부를 하나로 합친다.

### `배송담당`

해당 사람·식종 행의 배송 담당자다. 실제 배송 값이 `1`인 행을 리포트나 배송대타에 사용할 때는 빈칸일 수 없다.

### `연번`

담당자 안에서 같은 배송지를 묶고 정렬하는 선택 값이다.

- 같은 가구 구성원은 같은 배송담당과 연번을 사용한다.
- 선행 0을 보존하기 위해 Excel 셀을 **텍스트 형식**으로 입력한다. 예: `001`.
- 배송리포트와 확인서 템플릿은 한 가구 최대 5명까지 지원한다. 같은 배송지에 6명 이상이 묶이면 누락을 막기 위해 생성을 중단한다.
- 연번을 사용하지 않으면 GUI에서 **사용 안 함**을 선택한다. 출력의 배송 순번은 빈칸이 되며, 배송리포트는 서로 다른 대상자를 한 가구로 잘못 합치지 않도록 각 대상자를 별도 배송지로 계산한다.

### 주소 처리

- 확인서는 `관할동 + 도로명주소 + 상세주소`가 같은 사람만 한 가구로 묶는다.
- 같은 도로명주소라도 `101호`, `102호`처럼 상세주소가 다르면 서로 다른 가구다.
- 확인서와 주소 열이 있는 청구서에는 `도로명주소`와 `상세주소`를 공백 하나로 합친 전체 주소를 출력한다.
- `도로명주소`가 빈 대상자는 서로 다른 가구가 합쳐지는 것을 막기 위해 확인서 생성을 중단한다. `상세주소`는 비어 있어도 된다.

## 날짜 헤더와 배송 값

날짜 헤더는 `YYYYMMDD` 형식이다. Excel의 실제 날짜 셀도 읽을 수 있지만 표시와 관리 편의를 위해 문자열 `YYYYMMDD`를 권장한다.

| 셀 값 | 의미 |
|---|---|
| 숫자 `1` | 배송함 |
| 숫자 `0` | 일시중지 |
| 빈칸 또는 null 표기 | 중지 또는 전역 미입력/비배송 상태 |

숫자와 문자열 `1`, `0`을 같은 상태로 읽는다. 빈 셀과 `null`, `none`, 백틱(`` ` ``), 작은따옴표(`'`)는 빈칸으로 정규화한다. `O`, `X`, 그 밖의 상태 문자열은 허용하지 않는다. 배송 셀에는 수식을 사용할 수 없으며 `=1`, `=0`, `=""`도 로드 단계에서 거부한다.

빈칸은 열 전체의 상태를 먼저 판정한 뒤 해석한다.

- 해당 월의 모든 날짜 셀이 모든 배송행에서 빈칸이면 그 월은 **미입력** 상태다. 청구서를 만들 수 없다.
- 특정 날짜 열 전체가 빈칸이면 공휴일 또는 전체 비배송일이다. 배송리포트와 배송대타에서 제외한다.
- 입력된 날짜에서 특정 사람·식종 행이 숫자 `0`이면 **일시중지**다.
- 입력된 날짜에서 특정 사람·식종 행만 빈칸이고 같은 행의 이후 날짜에 숫자 `1`이 다시 나오면 **일시중지**로 자동 판정한다.
- 입력된 날짜에서 특정 사람·식종 행만 빈칸이고 이후 숫자 `1`이 없으면 **중지**다.
- 숫자 `0`만 있는 날짜와 월은 사용자가 상태를 입력한 것으로 본다. 실제 배송표에는 숫자 `1`인 행만 출력한다.

청구서의 조식 식수는 선택한 월의 토·일 입력 여부를 함께 본다.

- 선택 월의 모든 토요일·일요일 조식 셀이 빈칸이거나 주말 날짜 열이 없으면 기존 VBA 방식대로 조식 행의 각 `1`을 `3식`으로 환산한다.
- 토요일이나 일요일 조식 셀에 `1` 또는 `0`이 하나라도 입력되어 있으면 3배하지 않고 선택 월의 각 `1`을 `1식`씩 센다. 따라서 주말의 `0`은 일시중지로서 식수에 포함하지 않는다.

월 데이터를 전부 작성한 뒤 프로그램을 실행하는 운영 방식을 전제로 한다. 별도 완료 플래그나 자동 `1` 채우기는 사용하지 않는다.

## Excel 사용성 규칙

배포용 워크북은 다음 편집 보조 기능을 유지한다.

- `식종` 셀: `조식, 중식, 석식` 목록 유효성 검사
- 날짜 셀: 숫자 `1`, 숫자 `0`, 빈칸만 허용하는 유효성 검사
- 날짜 값 `1`: 초록색 조건부서식
- 날짜 값 `0`: 노란색 조건부서식
- `연번`: 텍스트 서식
- 헤더 행과 날짜 왼쪽 고정 열 고정, `db` 테이블 자동 필터
- ID 관련 열과 유효성 검사는 두지 않음

## 새 월 추가

1. `db` 테이블 안의 원하는 위치에 새 날짜 열들을 삽입한다.
2. 날짜 헤더를 `YYYYMMDD`로 입력한다.
3. 각 사람이 실제로 이용하는 식종 행의 상태를 작성한 뒤 프로그램을 실행한다.
4. 공휴일이나 전체 비배송일은 해당 날짜 열 전체를 비운다.

새 월을 왼쪽에 삽입해 기존 월이 오른쪽으로 밀려도 된다. 프로그램은 물리적 열 순서가 아니라 헤더의 실제 날짜를 파싱해 정렬한다.

## 연도 변경

- 한 파일에 여러 연도의 `YYYYMMDD` 날짜 열을 둘 수 있다.
- 파일을 직접 선택할 때 **DB 가져오기 설정** 창에서 사용할 연도를 고른다.
- 선택한 연도와 헤더 매핑은 비날짜 헤더 구조별 캐시에 저장된다. 다음 실행이나 새 파일 선택 시 비날짜 헤더 이름과 순서가 같으면 날짜 열이 달라도 설정 창 없이 재사용한다.
- 최근 20개 헤더 구조를 보관한다. 비날짜 헤더 이름이나 순서가 바뀌면 다른 구조로 판단해 설정 창을 다시 표시한다.
- 캐시한 연도가 없고 파일에 연도가 하나뿐이면 그 연도를 자동 선택한다. 여러 연도가 있으면 사용할 연도를 다시 선택한다.

## 도메인 조회 API

로드 결과에서 `RosterEntry`가 사람 객체다. 배송행은 ID 문자열 대신 같은 객체를 `DeliveryRow.person`으로 직접 참조한다.

- `book.rows_by_person[person]`: 그 사람의 식종별 배송행
- `book.get_delivery_row(person, meal)`: 사람 객체와 식종으로 한 행 조회
- `book.raw_delivery_value(person, meal, day)`: 원시 `1`/`0`/빈칸 상태 조회
- `book.effective_delivery_state(person, meal, day)`: 월·일 전역 상태까지 반영한 의미 조회
- `book.monthly_delivery_count(person, meal, year, month)`: 월 배송 횟수 조회

워크북에서 얻지 않은 별도 `RosterEntry`나 성명 문자열을 이 API의 사람 키로 넘기지 않는다.

## 파일 선택 시 검증 항목

- 선택한 워크북에 이름이 `db`인 Excel 테이블이 있는지
- `db` 테이블이 헤더 행을 포함한 유효한 범위인지
- GUI에서 식종·배송담당, 13개 인적사항과 비고 필수 역할을 모두 선택했는지
- 배송 순번과 인적사항을 포함해 선택한 각 역할이 서로 다른 헤더에 매핑되었는지
- 선택한 헤더가 `db` 테이블 안에 있는지
- 위치와 무관하게 날짜 헤더가 유효하고 중복되지 않으며, 선택 연도의 날짜가 있는지
- 각 비어 있지 않은 데이터 행의 식종 값에서 표준 식종을 하나만 찾을 수 있는지
- 위치와 무관하게 성명·관할동이 같고 생년월일 앞 6자리 또는 핸드폰이 같은 행을 한 사람으로 묶으며, 그 밖의 인적사항은 처음 나온 비어 있지 않은 값으로 보완하고 일반 불일치는 `DB검토` 시트에 기록할 수 있는지
- 배송 셀 값이 `1`, `0` 또는 빈칸/null 표기이며 수식이 아닌지

미매핑 `ID`의 빈칸·중복·외래키 유효성은 검사하지 않는다.

## 테스트 fixture

`assets/db2.xlsx`는 실제 개인정보가 없는 `db` 테이블 테스트 파일이다.

- 가상 명단 7명 × 조식·중식·석식 3행 = 21행인 레거시 호환 예시
- 각 사람의 13개 인적사항을 식종 행에 반복하고 식종은 `조식 → 중식 → 석식` 순서로 배치했다. 이는 fixture 구성일 뿐 모든 사람에게 3행을 요구하는 규칙은 아니다. 비고는 행별 입력 가능하다.
- 기존에 없던 식종 행의 일반 날짜는 빈칸으로 추가
- `2026년 6월·7월`은 기존 입력값이 남아 입력 완료 상태
- `2026년 8월`은 전체 빈칸으로 미입력 월 테스트
- `20260729`는 전체 빈칸으로 전체 비배송일 테스트
- `20260730`은 전체 빈칸인 또 다른 전체 비배송일 테스트
- `20260728`은 숫자 `1`과 개별 빈칸을 함께 넣고 이후 배송 여부를 확인해 배송·자동 일시중지·중지를 구분
- `기사A`, `기사B` 복수 담당자와 같은 가구의 동일 담당자·연번으로 가구 묶음 테스트
- 식종/배송값 유효성 검사, `1` 조건부서식, 텍스트 연번을 포함

프로그램 상단에서 `assets/db2.xlsx`를 선택하면 새 `db` 테이블 계약을 바로 검증할 수 있다.

파일을 직접 선택했을 때 같은 비날짜 헤더 구조의 캐시가 없으면 **DB 가져오기 설정** 창이 열린다. 사용할 연도와 각 프로그램 필드의 원본 헤더를 선택하고 **설정 적용**을 누르면 된다. 성공한 설정은 캐시에 저장되며, 같은 구조는 다음 실행이나 다른 파일에서도 자동 재사용한다. 상단의 **DB 가져오기 설정** 버튼은 캐시 여부와 관계없이 창을 열어 언제든 변경할 수 있다.
